# Primitives

Pistachio does not add every feature a person asks for. It keeps a small set of **primitives** — the things a browser is made of, each with verbs anyone can call — and a person asks their agent to build the feature they want on them, in their own copy: an extension the agent writes (`docs/extensions.md` §8), approved on a sheet, theirs. "Hide my football space until Sunday morning, and put it away again after the games" is not a feature with a settings page here. It is a space that can be **away**, a clock main keeps, and ten lines of an extension somebody's agent wrote for them.

This file says what a primitive must be to carry that, which ones exist, and the order the rest are built in. §2 (away), §3 (triggers: windows, instants, intervals, signals, events) and §4 (what the shell draws: the theme, marks, rows, menus) are normative for the code on branch `primitives`; §5 on is the plan, written so that what is built first does not have to be rebuilt for what comes after. It builds on `docs/extensions.md` (the extension, its broker, its sheet), `docs/spaces.md` (spaces), `docs/reminders.md` (the one clock main had before this).

## 1. What a primitive is

Eight rules. Each is here because a system that broke it paid for it, or because the first wish we tried to serve (the football space) could not be served without it.

1. **One table of verbs.** Whatever a person can do to an object — a space, a tab, a window — is one verb in main, reached the same way by the shell's menu, the agent's tool and an extension's call, refused by the same rules in the same sentence. Until this branch a space's commands were the shell's alone (`IPC.tabGroupCommand`): neither the agent nor an extension could so much as close one.
2. **State is the host's.** What must outlive the code that asked for it is main's, on the object, in main's file: a space that is away is away because main says so, not because an extension remembers it. An extension that crashes, is turned off or is removed strands nothing.
3. **The host owns the clock; the extension owns the decision.** No extension code sleeps until Sunday. Main keeps every time and every wake; code runs for a moment, decides, and stops. (Chrome's `alarms`, Raycast's `interval`; Home Assistant's delays, lost at every restart, are what the other way costs.)
4. **Ask what holds, do not wait to be told.** Anything that must survive a closed lid is checked, not fired: at launch, on wake, on unlock, and on a tick. A reminder more than fifteen minutes late is `missed` (`docs/reminders.md`), which is right for "tell me at 3" and wrong for "this space is here on Sundays".
5. **Declare when and where; code only what.** What an extension adds, when it runs by itself, and what it may touch are data in its manifest that main reads without running it — so the sheet says them in the shell's words and a change to them pauses the extension. What it does when it runs is code. No expressions in the manifest: a rule that needs an `if` is code.
6. **The host draws.** An extension never puts pixels in the shell's own chrome. It names a place the shell offers and hands over data — a mark, a line, a small tree of the shell's own elements — and the shell draws it, labelled as the extension's. (VS Code's refusal of its DOM; Claude Code's render sites; the shell's renderer is the one unsandboxed process here, `docs/extensions.md` X2.)
7. **Nothing acts unattributed.** What code changed while nobody was looking says so where it is: who, when, and the way back — drawn by the shell from main's record, never from the extension's words.
8. **A grant is for the thing, not the kind.** An extension is given *this* space — the one its command was run in — not every space. The worst a wrong extension does is get one space wrong. (The one exception is asked for by name, on a High line of its own: §2.6.)

And the test for what belongs in main rather than in an extension: it needs trust (enforcing, drawing, waking), it is an object's own truth, or two extensions would have to agree on it. *Away* is a space's own truth, so it is main's; *on Sundays* is somebody's decision, so it is theirs.

## 2. Away

### 2.1 What a person does

**Send a space away.** A space's menu has **Send away**, above *Close space*. The space leaves the rail whole; if it was in front, the desk passes on first, as it does for a closed one. Nothing of it stays loaded. A notice says *Football is away* with **Bring back**.

**See what is away.** While any space of the Profile is away, the rail has an **Away** tile at the foot of its spaces, with how many. Its card lists each: its colour and first favicons, its name, and one line the shell writes — *Away*, *Back Sun 8:00 AM*, *Back tomorrow 8:00 AM · Pistachio*, *Back Sat 8:00 AM · Game day* (who sent it, when it was not the person: the agent is *Pistachio*, an extension its name on the sheet) — and **Bring back**.

**Bring it back.** The same space: the same tabs in the same order, each asleep until shown, waking with its history and where it was scrolled; its Stack and its conversation, which never left; a favorite's page that was in it still that favorite's. It stands at the end of the rail, and is in front when the person brought it back themselves.

**Ask for a time.** There is no time picker, on purpose. "Hide this space until Sunday morning" is said to the agent, which sends it away with the time; main brings it back then — or, if the Mac was asleep or Pistachio closed, the moment it next looks — and says *Football is back* with **Show**. Nothing is brought in front by a clock. "Every Sunday" is not the agent's to fake with reminders: it is an extension with a trigger (§3), and the agent says so.

**What it is not.** Not the archive (`docs/tab-tidy.md` §3.6), which is where things are filed to lapse: an archive entry is pruned after the days Settings says, restores under new tab ids, and forgets a favorite's link. An away space is never pruned and comes back as itself. *Close space* still files to the archive.

### 2.2 The rules

- **Only a drawn space** can be away: not a Home tab's space, not a favorite's or pin's page (they are their tab's and their entry's).
- **Refused, with a sentence** (`AWAY_REFUSALS`), when the space is being shared live, one of its pages shares the screen or is being recorded, or the agent is at work in it — unless it is that very turn asking (the agent sending away the space it was asked to, from inside it).
- **It is the person's from then on** (`asPersons`): a space someone sent away is one they keep, and Tidy does not file it the minute it is back for having been idle all the while.
- **`until` is an instant**, in the future when asked. Main brings the space back at the first look at or after it: launch, wake, unlock, and a timer that never sleeps more than thirty seconds.
- **Room.** A Profile holds fifty drawn spaces (`MAX_TAB_GROUPS_PER_SPACE`), away ones not among them, and fifty away. A space due back with no room waits, says so on its row (*Due back · no room for it*), and is tried again every tick; brought back by hand, it is refused with the sentence. It is never dropped. **Room for its tabs** is asked the same way: a Profile's session is read back two hundred tabs at most, so a space whose tabs would take it past that stays in the file until tabs are closed (`hasRoomForTabs`, `AWAY_REFUSALS.tabsFull`) — put back, the session would have dropped them and the file let go.
- **A Profile that is gone** (removed on another device): its away spaces are the Profile in front's — listed there, timed or not, wherever the person is, and back there when the time comes or they are asked for (`AwaySpaces.list`, `#homeOf`). Nothing is left where no list shows it.
- **Every tab, or none.** The away file reads a space back as the session reads one, and that reading drops a page no relaunch reopens: an address longer than 2,048 characters, a blank page, a `blob:` one. Sent away, such a tab's page would be closed and the tab in neither file. So a send asks first (`BrowserController.awayUnkept`) and is refused before anything moves, naming the tab — *“Flights to Lisbon” cannot be kept while its space is away. Close that tab, then send the space away.* (an extension is told without the name: a title is `tabs:read`'s to see). What is taken is checked again against what the file will read back (`firstUnkept`), and a space that would be filed short is put straight back whole. A close nobody pressed asks the archive's own question the same way (`closeUnkept`, by the archive's reading of a tab): closed, the tab's page is gone, and Undo could not return what the archive's file does not hold. Both are asked twice: before anything moves, and again by the controller once the desk has passed on from a space that was in front (`takeGroupAway`; `closeTabGroup`'s `guard`) — a page can change in that moment.
- **Too many tabs.** What is read back of one space is two hundred tabs, from the away file as from the archive (`MAX_TABS_KEPT_OF_A_SPACE`). A space with more is not sent away, by anyone, and is not closed by code (`AWAY_REFUSALS.tooMany`, refused before anything moves): the rest would be dropped as it was filed. The person's own *Close space* is theirs, as it was.
- **Nobody is moved** but by their own press: only the person's *Bring back* puts the space in front.
- **This Mac only.** The file is not synced and is in no restore point; a space's Stack is synced under its id as before.

### 2.3 How it works

A space sent away leaves the session altogether and is kept in a file of its own, `<userData>/away-spaces.json`, as the slice of the session it was: a `DurableSpaceSession` holding that one space and its tabs. So what a restart keeps of a tab is exactly what a space keeps while away, the file is read with the session's own reading (`heldSpace` → `sanitizeTabSession`), and a field added to a tab or a space later is carried with no second list to keep in step. Nothing was added to `TabGroupInfo`, and none of the hundred places that walk the tabs learned a new case: to all of them an away space's tabs are simply not there.

`BrowserController.takeGroupAway` is *Close space* without the closing: the desk passes on (`#passFrom`), each tab is read as the session would keep it — its stack read from its page now — and discarded with no "recently closed". `putGroupBack` is a launch's restore for one space: its tabs asleep under their own ids, the space under its own, one page per entry (`claimIncomingEntries`: a favorite that has since opened its page elsewhere gets a plain tab back).

**Never in neither.** The away file is written at once and atomically, never debounced. A space is written there *before* it leaves the session (whose own save is debounced), and leaves there only *after* the session holding it again is on disk: a return writes the session at once and asks whether the write was made (`sessionWritten`; `TabSessionStore.flush` says). When it was not — a disk that is full — the space is back as far as anyone can tell, on no list of away spaces, and the file **keeps its copy**, through every later write of it, until a look at the clock (a tick on, and at quit) finds the session written (`AwayStore`'s `remove` with `keep`, `release`). A restart before then reads the old session, without the space, and the file, with it: away again, not lost. A crash can leave a space in both; launch keeps the session's (`AwaySpaces.start`) — the two are then the same space, a write apart. A file that cannot be written puts the space straight back and refuses.

**One at a time.** Sends, returns and ticks run through one queue (`#serial`): none interleaves with another across an await. **The window closing** ends the queue (`stop`): what is under way finishes, what waited behind it is not begun, and the controller refuses a space taken from or put into it once it has shut down — its session has had its last write, so the file keeps what it holds for the next window's clock.

**The verbs** are `AwaySpaces.send(groupId, { by, until?, ownTurn? })` and `bringBack(id, { select? })`, and every caller is a line: the shell's `sendAway` / `bringBack` group commands (`by: person`, `select`), the agent's tools (`by: agent`, never `select`), an extension's `pistachio.spaces.sendAway` / `bringBack` (`by` the extension, by its name on the sheet). `onChange` is what the notice and an extension's `onAwayChanged` are made from.

### 2.4 The agent

Four tools in a group of their own, `spaces`: `spaces_list` (the Profile's spaces and its away ones — until now the agent could not name a space), `space_send_away({ spaceId, at, inMinutes })` (a time read as a reminder's is), `space_bring_back({ spaceId })`, and `space_close({ spaceId })` (§2.6: into the archive — for a space the person is done with, never for "later"). The rule it is given: a space's coming and going is this, never a reminder; with a time it comes back by itself; a wish that recurs is an extension's.

### 2.5 Extensions

`spaces:write` (Medium): *Sends spaces away and brings them back.* `pistachio.spaces.sendAway(spaceId, { until? })`, `bringBack(spaceId)`, `away()`, `onAwayChanged(fn)`.

**Which spaces** (rule 8). An extension may send away a space the person **gave it by a gesture**: one of its commands run in that space — a Bar command (`ctx.spaceId`), a menu item (one in the space's own menu among them, §4.3), a key, its Ledge icon. The grant is kept on the extension's record, because a trigger (§3) acts on it with no gesture in hand. It may bring back a space it holds a grant for, or one it sent itself. A tool call the agent made is not the person's gesture in a space and grants nothing.

**Safe to ask twice.** Sending away a space it holds that is away already, and bringing back one that is here already, answer quietly and do nothing: a handler that reconciles (§3) asks for what should be so, not for a change.

**Nothing stranded.** An extension turned off everywhere, or removed, has the spaces it sent brought back — and a send of its that was still waiting its turn then, and lands after, comes straight back as it lands (`strandedOnSend`): the worker stopping does not cancel what the service had accepted.

### 2.6 Closing a space, and every space

Away is for *later*. The other thing a person does to a whole space is **Close space** — done with it: its tabs close and the space is filed in the archive as one entry, under its own id, one Restore away for as long as the archive keeps things (`docs/tab-tidy.md` §3.5). Until stage 6 that verb was the shell's alone, as away once was; and it is exactly what one of Pistachio's own features, Tidy, does to a space it gathered once all of it has gone idle. So it is one verb now (rule 1), `SpaceClosing.close(groupId, { by, unattended?, absent?, ownTurn? })` in `main/space-closing.ts`: the space's menu (`by: person`), the agent's `space_close` (`by: agent`), an extension's `pistachio.spaces.close(spaceId)`.

- **The person's own press is refused nothing.** Code is refused what sending a space away is — shared live, a page sharing the screen or recorded, the agent at work in it — and, asking with nobody there, the space in front (unless nobody is at the Mac: §3.6), one playing something, one with a terminal. The same check as away's (`awayBlock`), in a close's words (`CLOSE_REFUSALS`).
- **Its own capability, `spaces:close`** (Medium): *Closes spaces into the archive, where they can be restored.* An extension approved to send spaces away was not approved to close them, and a capability's sentence does not grow under an approval.
- **Said, and written down.** A close the person did not press is said in a notice — *Closed “Trip” · 2 tabs · Idle spaces* (the agent's says *Pistachio*) — with **Undo**, held until somebody is there to read it: the window in front, and a key or the pointer touched in the last half minute (a space taken from in front of a locked or idle Mac is not announced to an empty room; `held-notices.ts`, which the away notices use too — one notice a space, its latest coming or going in place of one still waiting; the newest three kept, the journal having the rest; each said only if still so; a window that closes before it came in front hands what waited to the next one, once its shell can hear — `windowChanged`); one made with nobody there is a journal line too, whose Undo restores the archive's entry **where it was, not in front** (`reopen`; `restoreArchiveEntry`'s `quiet`). An entry the person already restored, or removed, is nothing to undo. A restore asks for room as a return does — for the space, and for its tabs in the Profile's session (`NO_ROOM_FOR_TABS`) — and the entry stays until there is; and the verb stops with its window (`stop`), as away's does.
- **What an extension is told of a space** grew by what Tidy knew and the API did not: `lastActiveAt` (the latest of its tabs'; each tab's own on the tab) and `byPerson` — whether the person made it or made it theirs (named it, moved a tab into it, keeps a Stack or a conversation in it), or it grew from a tab of their own. False only for a space Pistachio gathered by itself that nobody has touched since: the line Tidy draws (`isTidysGroup`, `isPersonsGroup`), handed over as one bit so an agent-written extension draws the same one.

**Removed, an extension leaves what it closed where it is** — in the archive, each a Restore away — and since its journal goes with it, the person is told how many there are and where (*Idle spaces had closed 3 spaces that are still in the archive*).

**Every space** is rule 8's one exception, asked for by name: `spaces:all` (High) — *Acts on any of your spaces, not only the ones you ran it in.* With it every drawn space of a Profile the extension is on in counts as given (`holdsSpace`), here or away; what it may then *do* to them is its other capabilities' to say, and `spaces:all` alone does nothing. It is for a wish about spaces in general — "file the ones I am not using" — which no gesture in one space can grant. The sheet leads with it.

## 3. Triggers

An extension says **when it runs by itself** in its manifest; main keeps the clock and wakes it. Nothing of the extension's waits for a time.

### 3.1 What is declared

```json
"triggers": [
  { "id": "sunday",  "during": { "days": ["sun"], "from": "08:00", "to": "23:00" } },
  { "id": "morning", "at":     { "days": ["mon", "tue", "wed", "thu", "fri"], "time": "09:00" } }
]
```

- **`during`** is a **window** of the week on the wall clock. `days` are the days it starts on (every day when left out); `to` at or before `from` ends the next day; `24:00` is the end of its day. The worker is told whether it holds.
- **`at`** is an **instant** that recurs. The worker is told the latest one that came due.
- **`zone`** is an IANA zone; left out, the Mac's own, read each time — the window travels with the person.
- **`every`** is an **interval**, and **`when`** a **signal** — something main can see: §3.6. **`on`** is an **event** — something that happens: §3.7.
- No expressions, at most eight, and an extension that declares any needs a worker. A rule that needs an `if` is the worker's code.

### 3.2 What a person sees

**On the sheet**, between what it adds and what it can do: **Runs by itself**, a line a trigger in the shell's words — *Sundays 8:00 AM–11:00 PM* — and one sentence made from what it asks for (`runsLimit`), true of everything it may do then beyond looking and telling the person things: *With nobody there it can only send away and bring back spaces you gave it, open tabs behind what you are doing, talk to api.espn.com and ask Pistachio's AI. What it does to your spaces and tabs is listed, and can be undone.* — the second sentence only when something of it is listed (what it shows is not: it is removed where it is shown) — or, for one that asks for none of those, that it changes nothing of the person's. The line is made from the declared data alone (`triggerInWords`); no code of the extension's has run.

**A changed time waits.** A trigger added, or one whose days, times or zone changed, pauses the extension until the person has seen the new line, as a new capability does (`ExtensionGrant.triggers`, `widenedTriggers`). One taken out applies at once. And a changed trigger is **another trigger**: what the old one last heard is forgotten with it (`AutomationStore.keepTriggers`, by `triggerKey`), so it starts as a new one does — an interval quiet, an instant from now, a window said once — whatever id it kept.

**On the Extensions page**, under the extension: *Runs by itself* — each trigger, whether it is on now and when that next changes; a **Pause** switch; and **What it did**: every space it sent away or brought back with nobody there, newest first, each with **Undo** (a space brought back before it was due is sent away again *until then* — the line keeps the time — and not at all once that time has passed). Above the list, **Pause all**. Paused, an extension still runs when the person runs it. **What it did** outlives the triggers: an update that takes them out of the manifest leaves the block with the journal alone — no Pause, there being nothing to pause — so every Undo is still there (`hasRunsBlock`).

**In the window**, as for any send or return: a notice with the way back — *"Football" is away · Game day* with **Bring back**, *"Football" is back · Game day* with **Show** — held until the window is next in front.

### 3.3 The rules

- **Asked, not fired.** Nothing happens AT a time. Every look at the clock — launch, wake, unlock, an approval, a pause lifted, and a timer that never sleeps more than thirty seconds — asks each trigger what holds now, and the worker is told **when that is not what it last heard** (`automation.ts` keeps what each heard). A lid closed across Sunday morning opens to one delivery; one closed across the whole of Sunday to none; a restart to nothing twice.
- **Read again before each run.** A look delivers one trigger at a time, and a handler can run for seconds — long enough for the folder to be saved or the extension turned off. Before each delivery the runner asks what is declared *now* (`#stillDeclared`): a trigger taken out, or declared otherwise since the look began, is not run as it was; the next look reads what is there.
- **Handlers reconcile.** The handler is handed the state (`{ holds }`) and makes the world match. It is not told a transition and must not count on having heard the one before.
- **A hand override sticks** until the answer next changes: bring the space back on Wednesday and it stays — off was heard on Sunday night, and off is not said again.
- **Heard means it answered.** A handler that throws, rejects or times out (ten seconds) was not heard, and is run again — a minute on, then two, five, fifteen, and every half hour — until it answers or the clock's answer has changed anyway. A retry that comes due while it cannot be made (its signal not known, everything paused) waits for the next look; the clock never spins on it. So a handler **returns its promise**, and what it could not do yet is done when it can be.
- **An instant never fires for the past** of an extension: what came due before it was first seen is where it starts. A window is said once at first sight, so the worker can make things match.
- **Unattended.** A worker's call is unattended while a trigger's handler is in hand and nothing of the person's is — no Bar command, menu item, key, click or agent turn of theirs in flight, no press in the extension's views in the last five seconds (`ExtensionScope.unattended`). Then only the methods in `EXT_UNATTENDED_METHODS` are answered: reading tabs, spaces and the desk; its own storage and data files; a toast, a badge, a status, a notification; `net.fetch` to its hosts; `spaces.sendAway` / `bringBack`; and `tabs.create`, behind what is in front (§3.7). Everything else is `PERMISSION_DENIED` — closing, showing or navigating a tab, reading a page, writing a note, the clipboard, staying up (`runtime.keepAlive`). The list is an allow-list: a method added later is closed until someone decides it is safe with nobody there. To do more, the handler shows a toast with an action; the person's press is attended.
- **Not from under the person.** Unattended, a space is not sent away while it is in front, while something in it is playing, or while it holds a terminal (`AWAY_REFUSALS.inFront`, `playing`, `terminal`). The handler fails, and the retry sends it once that has passed: a space due away at eleven goes when the person leaves it. The space in front does go when main can see it is in front of no one (§3.6, *Nobody there*).
- **Written down.** Every unattended send and return — and every theme set and tab opened — is a line in the journal: who, which trigger, what, which space, written by main as it happens. **Undo** puts the space back where it was (as the person's own act), takes the theme off, closes the tab; and the line says *Undone*.
- **Woken code does not stay.** A worker a trigger started is stopped as soon as no trigger's handler is in hand any more, unless the person has since run something of the extension's or one of its pages or its panel is open. Its timers are not a way to wait. Deliveries overlap — the clock's queue and each event's are not one — so the question is asked once, of them all (`stopsWhenSettled`). **And it is unattended from its first line to its last**, not only between a handler's start and its answer: the trigger is in hand before the worker is so much as started (its module's own top level runs as it loads), a woken worker is with nobody there for as long as nothing of the person's has run in it (`ScopeDeps.woken`), and one that has been stopped is answered nothing — a call it sent as it went is not a later, freer one. A woken worker that is **kept up** — a page of the extension's open, a hold — is not stopped, and is still the trigger's (`staysWoken`): a timer its handler set calls as with nobody there, until the person runs something of the extension's — a command, a click, or a message that follows their press in one of its own views; a message the open page sends by itself is the extension talking to itself, and is nobody (`attendedInvocation`). A page being open is not their hand on the worker. A worker the *person* started is neither kept nor cut short by a trigger: a trigger is not use of it (`WorkerHost.start`'s `quiet`; what a handler calls with nobody there does not wind the idle clock), so it idles out when it would have.
- **A handler main stopped waiting for is still in hand.** Ten seconds, and main gives up on a trigger's handler — but the handler is still running in the worker, and has not answered. Let go of then, it would call on as nobody's: in a worker the person had started, freely. It stays in hand (`staysInHand`, the entry's `lingering`) until its answer comes or the worker stops, and what it calls meanwhile is asked as with nobody there, and written down under its trigger.
- **The microphone and the camera are not a trigger's.** `getUserMedia` is the page's own call, not one of Pistachio's, so the list never sees it: main's permission handlers ask the same question (`ExtensionScope.mediaAllowed`), and a worker with nobody there is refused what its grant would allow. The extension's own page or panel, and its worker with the person's command in hand, have it as before.
- **A signal that chases its own tail is stopped.** A handler that sends away the space whose tab its own signal counts turns the signal off, brings the space back, turns it on. A signal's handler that has **acted** — done something written down, to a space or a tab — eight times in two minutes (`RUNAWAY_COUNT`), heard or failed, pauses the extension, as the person's own Pause would, and the notice says what happened (*it changed your spaces or tabs 8 times in two minutes*), not why. A handler that only looks, shows rows or tells the person something runs as often as its signal changes: the person's own browsing changes a signal too.
- **A window is needed.** Triggers are delivered only while a window is up: what a handler does, it does to the browser.

### 3.4 How it works

`triggers.ts` (main) reads a declared trigger against an instant and a zone on the reminders' wall-clock math (`wallClock`, `zonedTimeToUtc`): the stretches a window is on around now, those that touch joined so midnight does not blink, and the next change. It is pure; the same function answers the runner's tick, `pistachio.triggers.get`, the Extensions page and the status file.

`TriggerRunner` is the clock: one queue, a timer to the next change or retry capped at thirty seconds, and `deliver`, which is `ExtensionService.#invoke` with a new kind, `trigger` — the one invocation nobody's hand is behind, so the scope knows (`beginInvocation(id, profile, kind, name)`).

`AutomationStore` is `<userData>/extension-automation.json`: what each trigger last heard, each extension's pause and *Pause all*, and the journal (the newest four hundred lines). Written whole, at once.

The worker's side is `pistachio.triggers.on(id, fn)`, `get(id)` and `list()`.

### 3.5 For whoever writes the extension

`.pistachio/status.json` gains `triggers`: for each, `says` (the sheet's line), `zone`, `holds`, and `next` — every change of the next seven days, as the zone's clock reads and as an instant. It is written on every load, from the manifest, **with no code run**: an agent that has just saved `pistachio.json` reads the week ahead and checks it against the wish before the person is asked to approve anything. The author turn's instructions say to.

This replaces the `extension_test` tool first planned (a shadow scope answering with a week's effects). That would have run code the person has not approved; the schedule is where an agent ships the bug that only shows next Sunday, and the schedule is data.

### 3.6 Intervals and signals

Two more kinds of trigger, on the same clock and under the same rules (§3.3): asked and not fired, heard once, reconciled to, retried, unattended, written down, paused by the same switch.

```json
"triggers": [
  { "id": "sunday",    "during": { "days": ["sun"], "from": "08:00", "to": "23:00" } },
  { "id": "scores",    "every":  { "minutes": 5, "while": "sunday" } },
  { "id": "standup",   "when":   { "calendar": { "title": "stand-up", "early": 2 } } },
  { "id": "unplugged", "when":   { "power": "battery" } }
]
```

**An interval** (`every: { minutes, while? }`, one minute to a day) runs on the clock's own marks — every five minutes is :00, :05 — so its answer is *the latest mark*, as an instant's is the latest occurrence: a lid closed for an hour opens to one call, a restart to none twice. The marks are the **wall clock's**, counted from the day's own midnight on the Mac's clock (`intervalMarks`): every hour is on the hour in Kolkata as in New York, every two hours is on the even hours, every day is midnight; a rhythm that does not divide the day (every ninety minutes) starts over at midnight, its last stretch the short one. They are counted in time passed since that midnight, so on the two days a year the clocks change none is skipped and none comes twice — and a rhythm longer than an hour is an hour off its usual hours from the change until the next midnight. (First built on multiples since 1970, which put *every hour* on the half hour for a zone half an hour off.) A window shorter than the rhythm may hold no mark, and then none is promised: the status file lists nothing for it. `while` names a window or a signal declared beside it, and the interval runs only while that one holds; the sheet says the two together in the shell's words, never an id (*Every 5 minutes, Sundays 8:00 AM–11:00 PM*). It **starts quiet**: at first sight, and each time what its `while` names comes to hold, the mark then current is where it starts and the next is the first it hears — the window's own handler has just said how things are. This is how rows are right at nine as well as at eight (§4.5), and why a worker never stays up to poll. A minute is the floor: a worker woken more often than that is a worker that stays.

**A signal** (`when`) is one thing main can see, said so that it **holds or does not**:

| `when` | Holds while | Read from |
| --- | --- | --- |
| `{ "power": "battery" \| "plugged" }` | the Mac runs on its battery / is plugged in | the power monitor; a look when the charger changes |
| `{ "network": "offline" \| "online" }` | the Mac has no network / has one | `net.isOnline()`, each look |
| `{ "display": "external" }` | a second display is connected | the screens; a look when one comes or goes |
| `{ "idle": { "minutes": N } }` | nobody has touched the Mac for N minutes | the system's idle time, each look; every five seconds once it holds, so a return is heard promptly |
| `{ "calendar": { "title", "early"? } }` | an event with that phrase in its name is on, from `early` minutes before | the Google Calendar connected in each Profile the extension is on in, read every five minutes for the day ahead |
| `{ "screen": "locked" }` | the Mac's screen is locked | the system's idle state; a look as it locks and unlocks |
| `{ "page": { "host", "path"? } }` | a tab is on a page of that site (with `path`, one whose path starts with it) | the person's listed tabs the extension could see; a look whenever the tabs change |
| `{ "space": "front" }` | a space the person gave the extension is the one in front | the same |
| `{ "tabs": { "over": N } }` | more than N tabs are open | the same |

- **One bit, and the sheet's line is all of it.** The extension is told whether the signal holds — `{ holds }`, the shape a window's handler gets — and so, by when it is told, when an event with that phrase starts and ends. Nothing else: not the event's name, its guests or its place, not any other event, not how long the Mac has been idle. There is no call that reads the calendar. So a signal needs **no capability**: what it can learn is exactly the line the person approved (*While a calendar event with “stand-up” in its name is on*), a changed phrase is a changed trigger and waits on the sheet (`triggerKey`), and a phrase must be three characters at least so it is not every event. The plan said "each a capability with its sentence"; built, the trigger's line *is* the sentence, and a capability beside it would say the same thing twice and grant nothing more.
- **A level, not an event.** "A download finished" is something that happened; "the Mac is on battery" is something that is so. Only the second can be asked again after a closed lid, so only the second is a signal. (Things that happen are §5, stage 5b.)
- **Not known is no answer.** A signal main cannot read — no calendar connected, the reading run out — is neither on nor off: nothing is delivered, what the worker last heard stands, and `triggers.get` says `known: false`. A calendar that drops for an hour sends nobody's space away. An interval whose `while` is a signal not known is not known either, rather than stopped (`readTrigger`): the moment at launch before the calendar is read does not lose it its place. The Extensions page says *Not known · Connect Google Calendar in Settings*.
- **Nothing is read for a draft.** The signals are read only for an extension that may run. Before approval its status file says neither on nor off for a signal — main could tell, and does not — and nobody's calendar is asked for on an unapproved manifest's word.
- **The calendar is kept, not asked at the look.** `CalendarKeeper` holds the last reading (the events that touch the next twenty-four hours) and reads again behind a look, every five minutes while something that may run wants it; a look at the clock never waits on the network, and knows an event's start to the second. A read that fails leaves the last one in place until it runs out, and is tried again in thirty seconds rather than five minutes (a Mac wakes without its network), then twice as long each time it fails again, up to five minutes; one that says nothing is connected drops it at once. **A day read in part is not a day**: when one of the person's calendars could not be read, or the list of them, or there are more ticked calendars than the eight that are read, or more events in one than a page holds (`CalendarAgenda.partial` — the home page shows what there is all the same), the reading is taken as not made, for "no stand-up" is not something half a day can say. What is read whole is **kept whole**: nothing is cut from the end of a long day, from the end of a long name, or to fit one Profile's day beside another's, and a reading past any length main will keep (a thousand events, `CALENDAR_EVENTS_MAX` — more than one read can give) is not known rather than its first part. And a calendar whose grant has died is a calendar that is *there and cannot be read* (`blocked`), not no calendar: what was read of it is let go and the whole is not known, with *Reconnect Google Calendar in Settings*. An account signed in or out drops what was read at once. **A Profile is the boundary**: an extension's signal is read against the calendars of the Profiles it is on in — whichever of them is in front — and a Profile's calendar is never read for an extension that is off there. For the stand-up on the work calendar to be heard while the person is in Personal, the extension is on in Work. Of an extension's Profiles, one with no calendar is left out, and one that cannot be read makes the whole not known — half a day's events would say a meeting is not on when it is.
- **The browser's own are signals too.** A page of a site open, a space in front, the tabs' count: each a level, read from the tabs main already has at every publish (`tabsChanged` → `#browserSignalKey`: the clock is looked at when one's answer moved, never on a timer). What is read is what the extension could see — the person's listed tabs in the Profiles it is on in, never an agent's hidden tab, never another extension's page — and what it is told is the one bit. A page's `host` is a site by name, or `*.google.com` for it and the sites under it; never a scheme, a port, every site, or a whole ending (`*.com`, `*.co.uk` — the common country ones; the Public Suffix List is not carried). No window up is *not known*, as an unread calendar is. "Send Football away while a Meet call is open" is `{ "page": { "host": "meet.google.com" } }` and the two lines of §6.
- **Nobody there.** With nobody there is the common case for a signal, and for `idle` and `screen` it is the definition. A space is not sent away from in front of the person (§3.3) — but when main can see that it is in front of no one, it may go: the screen is **locked**, or the handler in hand is that of an `idle` or `screen` signal (or of an interval that runs `while` one) and the signal **holds as read at that moment** (`#nobodyThere`, `signalSaysNobody`; `AwaySpaces.send`'s `absent`). So "send Work away when I have been gone ten minutes" does what it says, and a window's handler that happens to run while the person reads without touching anything does not: only the trigger that *says* nobody is there carries the leave. What is playing, and a terminal, are still not taken. (The plan left this undecided; built, the leave is the trigger's own line on the sheet — *While nobody has used this Mac for 10 minutes* is what the person approved.)

`.pistachio/status.json` lists an interval's next three marks and a signal's `holds` and `needs`; a signal has no `next` — when it changes is not the clock's to say.

For a spec: `PISTACHIO_E2E_SIGNALS=<file>` holds what main reads — `{ battery, online, displays, idleSeconds, locked, calendar }`, `calendar` left out for one not connected — beside `PISTACHIO_E2E_TRIGGER_CLOCK`.

### 3.7 Events

Rule 4 says to ask what holds. Some things do not hold: they **happen** — a tab opened, a page arrived, a download finished — and cannot be asked again after a closed lid. They are a fifth kind of trigger, and the one that is honestly second-class.

```json
"triggers": [
  { "id": "opened", "on": { "tab": "opened" } },
  { "id": "pr",     "on": { "page": { "host": "github.com", "path": "/pulls" } } },
  { "id": "done",   "on": { "download": "finished" } }
]
```

| `on` | Happens when | The sheet says |
| --- | --- | --- |
| `{ "tab": "opened" \| "closed" \| "shown" }` | a tab the extension could see opens, closes, or comes in front | *When a tab opens*, *When a tab comes in front* |
| `{ "page": { "host", "path"? } }` | a tab arrives at such a page: a new tab on it, or one that navigates to it (a jump within a page is not an arrival) | *When a page under github.com/pulls opens* |
| `{ "download": "finished" }` | a download completes, in a Profile the extension is on in | *When a download finishes* |

- **Told once, soon, or never** (`trigger-events.ts`). That is what "missed" means: an event is told only while Pistachio is up with a window, the extension may run, and nothing has it paused. What happens otherwise is missed, and nothing makes up for it — no catch-up at launch, none when a pause lifts. A pause — one extension's, or *Pause all* — also drops what was gathered and not yet told (`forget`, `forgetAll`), however soon it is lifted; and either one lifted tries a trigger that had failed at once, not when its retry would have come (`forgive`, `forgiveAll`). A handler that fails **was told**: the failure is logged and the event is not said again (a level's handler is retried because the level is still there to reconcile to; an event is not).
- **Told together.** Events are gathered for a moment (300 ms) before the worker is woken, one trigger's handler runs at most once in three seconds, and what piles up meanwhile is handed to the next run — the newest twenty. A hundred tabs opened at once are one start of the worker.
- **That it happened, and to which tab.** A handler gets `{ events: [{ at, tabId? }] }`: never an address, a title or a file's name. Reading the tab is `tabs:read`'s to allow (`tabs.get`), on its own line of the sheet. The trigger's line is, as for a signal, the whole of what the event itself tells.
- **A space that moves is not its tabs closing.** Sent away or brought back, a space takes its tabs with it: none of them was closed, none opened. The away service counts its moves (`AwaySpaces.moves`, `movedSince`) and says when one is under way (`moving`); whoever watches the tabs asks whether a tab's space moved since it last looked — which holds whichever side of the away file's writing a look falls on, and at a launch, where a space due back returns before anything saw it away. Each tab's space is written down at every look. The window's first tick, and a launch's restore, open nothing either.
- **Heard is a handler that answered.** *Last heard* is set only when the handler ran and answered, for a trigger still declared by an extension still there.
- **The handler is unattended** like any trigger's: the same allow-list, the same journal, the same pause.
- **Not a level.** An interval's `while` cannot name an event, `triggers.get` answers `events: []`, the status file lists no schedule for one (`event: true`), and the Extensions page says *Last heard today 2:14 PM* or *Not heard yet* in place of on, off and next.

**A tab opened with nobody there** is the one verb stage 5b added to the unattended list (`EXT_UNATTENDED_METHODS`): `tabs.create` from a trigger's handler opens the tab **behind** what is in front, whatever `show` asked — nobody is moved by code — at most twelve an hour, and writes a journal line (*Opened docs.google.com/document/d/1*) whose **Undo** closes it — wherever the tab is now: moved to another space that has since gone away, it is away with that one, and Undo says so rather than calling it undone (`undoOfOpenTab`, `AwaySpaces.holdsTab`). **Behind needs something in front**: a space shows the tab it has, so one that joined the space in front while nothing is in use there would be put in front whatever was asked. With nobody there that is refused (`UNAVAILABLE`, not counted against the hour), and the trigger is run again later — the page opens once the person is somewhere. It is **a page of the web, in a space that is there**: never one of the extension's own pages — that is its code running in a view nothing holds to the unattended list, `ui.openPage` by another name — and never a space made for it: not `space: "new"`, and not a Home tab's space or a favorite's page's by its id, which would grow into a space on the rail around the new tab. The space in front, or a drawn one by name. "Open my stand-up doc every weekday at nine" is an `at` trigger and one call. Closing, showing and navigating a tab stay the person's.

### 3.8 A question to a model

`pistachio.ai.complete({ prompt, system?, maxTokens? })` → the answer's text. Capability `ai` (High): *Sends what it chooses to Pistachio's AI and reads the answer (spends your AI usage).*

One question to the account's fast model — the one Tidy names a space with — and nothing else: no tools, no memory, no turn in anybody's conversation. It is what a feature needs to name, sort or sum something up, and what `agent.ask` (a visible turn, filled into the Bar for the person to send) is not. Tidy's own gathering is a call like it.

- **What leaves is the extension's to choose**, and is already bounded by what its other lines let it see; the ledger notes that it asked and how much it sent, never the words.
- **No model is not an error to recover from, it is a case.** Signed out, offline, switched off, timed out: `UNAVAILABLE`, and the extension does the plain thing — as Tidy archives by the clock alone when it cannot ask (`docs/tab-tidy.md` §1, "Degrades to Arc").
- **Bounded.** Ten a minute; with nobody there, twelve an hour (`aiAsked`) — a trigger that runs every minute does not spend the person's usage every minute. A prompt of 24,000 characters, an answer of 2,000 tokens.
- **Inside the handler that asks.** An answer may take twenty seconds, and a trigger's handler has ten: asked from a handler, the wait is cut to what the handler has left, less a second and a half kept for acting on the answer (`handlerTimeLeft`, `AI_HANDLER_MARGIN_MS`) — so `UNAVAILABLE` comes while the fallback can still run, not after main has given up on the handler. With under a second left nobody is asked. The request itself stops at that time, and at once when the view that asked is gone — a woken worker stopped, a page closed, the extension turned off (`CompleteCalls`): nothing is asked on, and paid for, for nobody.
- For a spec: `PISTACHIO_E2E_COMPLETE` is a JSON object of answers by a fragment of the prompt; without it a spec run asks nobody.

## 4. What the shell draws

Rule 6: an extension never puts pixels in the shell's own chrome. It names a place the shell offers and hands over a **value**; main keeps the value, the shell draws it, labelled as the extension's, and the person takes it off in one press. Nothing of the extension's runs to keep it there — a worker a trigger woke has stopped long before anyone looks.

Such a place is a **render site**. Each is a row in main, not a new kind of thing: who may fill it (a capability or a line of the manifest, and a space the person gave the extension where it is a space's), what it takes (a small checked value), how many may hold it, and whether what fills it with nobody there is written down.

| Site | Filled by | Holds | With nobody there |
| --- | --- | --- | --- |
| A space's tile on the rail: a **mark** | `pistachio.spaces.setMark(spaceId, { glyph?, tone?, label } \| null)` — `spaces:mark` (Low), a space it was given | one for each extension; the tile draws the first | allowed, not journaled: it says whose it is where it is |
| A tab's row in the sidebar: a **mark** | `pistachio.tabs.setMark(tabId, { glyph?, tone?, label } \| null)` — `tabs:mark` (Low), any tab it could see (§4.7) | one for each extension; the row draws the first | as a space's |
| The desk's well: a **backdrop** | `pistachio.theme.set({ backdrop, spaceId? })` — `theme` (Medium); for one space it was given, or for every space | one holder for each scope | allowed, journaled with Undo |
| The shell's **accent** | `pistachio.theme.set({ colors: { accent }, spaceId? })` | as the backdrop | as the backdrop |
| The **band**: a strip beside the Bar | `pistachio.ui.band.set({ rows, spaceId? })` — `"band": true` in the manifest; for one space it was given, or for every space | each extension its own, six rows; the lane holds eight chips in all | allowed, not journaled: it stands under the extension's mark, with its × |
| A **section** of the sidebar | `pistachio.ui.sidebar.set({ title?, rows, spaceId? })` — `"sidebar": true` | each extension its own, twelve rows; four sections drawn | as the band |
| A space's own **menu** | `contextMenus` with the `space` context, in the manifest | every extension's items, under the shell's caption | — (a press) |
| A tab's own **menu** | `contextMenus` with the `tab` context | as the space's | — (a press) |

### 4.1 The theme

`pistachio.theme.set({ backdrop?, colors?: { accent? }, spaceId? })` replaces the extension's theme for that scope whole — a handler says what should be so, as often as it likes — and `theme.clear` takes it off. A space's own is drawn there, field by field, over one for every space.

**A backdrop is a value**, one of three: a colour; a gradient of two to four colours at an angle; or a picture from the extension's own folder (`.png .jpg .webp .svg`), fitted to `cover`, `contain` or `tile`, and dimmed toward the shell's ground as far as `dim` says (to 0.8). Main copies a picture into its own keeping when it is set — checked to be inside the folder and to be the picture its name says, kept by its hash, served to the shell at `pistachio-ext://theme/<file>` — so the shell never draws from an extension's address and nothing the folder does later changes what is shown. An agent that writes extensions writes text: the picture it can make is an SVG, which is drawn as an image, its scripts never run.

**Where it is drawn.** In the desk's well (`.desk-stage`), under every window, clipped as the well is (`--desk-notch-clip`), with the well's pressed-in edge over it. The Bar's nub is a hole in the well down to the shell's ground — so the nub, the surface's gutter, the notch view that paints the nub and the native glass under it are untouched, and there is one painter of a backdrop, not three. (The plan had three: it took the well's ground for the window's. The well is inside it.) Two layers cross-fade when the backdrop in force changes — a space switch, a set, a clear. The empty desk's words stand on a plate of the shell's surface while a backdrop is behind them.

**The accent** is the one colour token: the colour the shell tints its surfaces with and draws its focus ring in. It must show on the light ground and the dark one — 2:1 against each — or `theme.set` is refused with the ratio (`accentRefusal`). Unlike the backdrop it must reach every view: the Bar's nub and the notices are views of their own, and each mixes the accent into its ground. So main lays it over the appearance every view is already told (`AppearanceSettings.accentOverride`, never stored; `shownSettings` in main's `index.ts`) and says the settings again when the space in front changes or a theme does — and answers a change of the person's own settings the same way, so the settings the shell keeps from that answer are the ones every view was told. The person's own palette is untouched, and is back the moment the theme is gone.

**One holder for each scope.** A theme set for a space (or for every space) takes the place of whoever's was there; `theme.get` then answers the displaced extension null.

### 4.2 Marks

A mark is one or two characters — a letter, a digit, an emoji; a dot when none — in one of five tones, with a label. The shell draws it at the corner of the space's tile and says it as *Game day: Games on* (the tile's label for a screen reader, a line on the rail's hover card): the extension's words only inside the shell's frame.

### 4.3 A space's menu

A `contextMenus` item with the `space` context is offered in a space's own menu, under the caption *Extensions*. Choosing it wakes the worker with `info.spaceId` and **gives the extension that space** — it is the person's hand in the space, as a Bar command run there is. The grant is recorded for an extension holding any of `spaces:write`, `spaces:mark` or `theme`.

### 4.4 The person's side

- **The space's menu** names a backdrop in force there and takes it off: *Remove backdrop · Game day*.
- **Rows carry their own ×**: on a sidebar section's head, and at the head of a strip — the extension's mark turns into it under the pointer (§4.5).
- **The Extensions page** lists, under the extension, **What it shows** — *Backdrop and accent on "Football"*, *Mark on "Football" · Games on*, *Strip beside the Bar on every space · KC 21 – BUF 17*, *Sidebar section on "Football" · Today's games* — each with **Remove**; and a theme set with nobody there is in **What it did** with **Undo**.
- **Removed by hand, it stays off** until the extension next has reason to set it: a trigger's answer that has not changed is not said again (§3.3).
- **Turned off or removed**, an extension takes its marks, its theme and its rows with it. Off in one Profile, they are not drawn there.

### 4.5 Rows: the band and the sidebar

Two places take **rows**: the **band** — a strip along the desk's foot, beside the Bar — and a **section** at the foot of the sidebar's card. `pistachio.ui.band.set({ rows, spaceId? })`, `pistachio.ui.sidebar.set({ title?, rows, spaceId? })`; each also `clear`, `get` and `onPress`.

**A row is the shell's own, with slots — not a tree.** `{ text, detail?, value?, mark?, id?, buttons? }`: what it says; a quieter detail after it; a value at its trailing end in figures that line up; a leading mark (a glyph of one or two characters, or a dot, in one of the five tones); an id, with which it can be pressed; and at most two buttons. Every string is one line and bounded (80, 80, 24, a button's title 24). The plan said "a small tree of the shell's own elements". Built, it is a row with named parts, because the same value is drawn in a thirty-pixel strip and in a 224-pixel sidebar, in light and dark, by two renderers (the shell, and the notch view over a live page): the shell has to decide what gives way first — the detail, wholly, before the text loses a letter — and a free tree cannot say. A new kind of element is a new field, checked like these. Nothing an extension hands over is markup, a URL to draw, a colour or a size.

**Declared, not granted.** `"band": true` and `"sidebar": true` in the manifest (rule 5): the sheet says *a strip beside the Bar*, *a section in the sidebar* under what the extension adds, an approval's hash names them, and `set` for a place not declared is refused with the line to add. No capability: a row shows the person the extension's own words under its own mark, and reads nothing of theirs — the same standing as its panel, or the live pill (`ui.setStatus`) that needed none before this. A space's own rows still need that space **given** (rule 8), and declaring a place is enough for a gesture to record the space.

**Kept by main** (`ShownStore`'s `sites`): one view for each extension, place and scope, replaced whole by `set`; no rows is `clear`. There after the worker has stopped and after a restart. Read back from the file through the same bounds, so nothing the file holds can be drawn that `set` would have refused. **A space's own rows are drawn there instead of the extension's every-space ones** — never both.

**The band is the Bar's lane.** The live pills (`ui.setStatus`) already lie there: the nub drawn out along the foot, a hole in the well, drawn by the shell and — over a live page — by main's notch view, the same row in both. A band's rows are chips in that lane: an extension's rows together in one pill, in the rows' own order, led by the extension's mark. So the band needed no new geometry, no cover and no room kept on the desk; and like a live pill it lies *over* the foot of a page that reaches the lane (§7). The lane holds eight chips in all, live pills first. `setStatus` stays what it was — something live that ends with the work, held in memory, gone at a restart; the band is what should still be there tomorrow.

**The section** stands between the card's view and the Ledge, under a hairline: a head (the extension's mark, the title it gave or its name, and on hover a ×), then its rows. Sections share at most 38% of the card and scroll past that; four are drawn. A row's buttons come up in its value's place while the pointer is on the row.

**A press** on a row with an id, or on a button, goes to main (`{ type: "press", id, site, scope, row, button }`), which looks the row up **in the rows it keeps** — never in what the shell says they were — and wakes the worker with a new kind of invocation, `press` (`pistachio.ui.band.onPress`): `{ site, row, button, spaceId }`, the space in front. It is the person's hand (`EXT_ATTENDED_KINDS`), so its handler may do what a trigger's may not. It **grants nothing**: pressing "KC 21 – BUF 17" is not giving the extension the space in front. Rows that can be pressed are refused an extension with no worker. A press for a row no longer there does nothing, quietly.

**With nobody there** `set`, `clear` and `get` are allowed and not journaled: as a mark, rows say whose they are where they are, and their × is beside them.

### 4.6 A tab's menu

A `contextMenus` item with the `tab` context is offered in a tab's own menu — a right-click on its row in the sidebar — under *Extensions*, for a page the item's `hosts` allow. Choosing it wakes the worker with that tab (`info.tabId`, `info.fromTab`), and is a gesture on the tab and in its space as a window's ⋯ item is. Main checks the item is one declared for a tab's menu, that the tab is here, and the hosts against the tab's address as *main* has it. An agent's own tab offers none.

### 4.7 A mark on a tab

`pistachio.tabs.setMark(tabId, { glyph?, tone?, label } | null)`: a space's mark (§4.2), on a tab's row in the sidebar — drawn after the title, said in its tooltip and to a screen reader as *Unread: Not read yet*.

**Which tabs is the capability's to say, not a gesture's.** A space is given by a gesture and the grant is kept. A tab cannot be given that way: a tab's gesture grant lapses when the page moves to another site — rightly, since it lets the extension *read* the page — and a mark that fell off at the first link would be no mark; and the wishes are about tabs in general ("the ones I have not read"), not this one. So `tabs:mark` (Low: *Puts a small mark on your tabs.*) reaches any tab the extension could see: the person's listed tabs in the Profiles it is on in, never an agent's hidden tab, never another extension's page. It reads nothing: the mark is the extension's own words in the shell's frame, and an extension learns which tabs there are only by `tabs:read` or by an event's tab (§3.7).

**Kept by the tab's id** (`ShownStore`'s `tabMarks`), one an extension a tab, two hundred an extension. A tab that **closes** takes its marks with it — main drops them as the tab goes, with no code of the extension's (`tabsChanged` → `dropTabs`) — and one whose space only went away keeps them for when it is back. Taking a mark off a tab that has gone is quiet.

**The person's side.** The Extensions page lists them as one line under *What it shows* — *Marks on 3 tabs · Not read yet* — with one **Remove** for all of them; turned off or removed, an extension takes them with it.

**A tab coming in front is an event** (`{ "tab": "shown" }`, §3.7), added with this: "read" is the tab having been looked at, which nothing else says once the worker has stopped.

## 6. The football space

```json
{ "api": 1, "id": "dev.me.game-day", "name": "Game day", "version": "1.0.0",
  "permissions": ["spaces:write"],
  "worker": { "type": "web", "main": "worker.js" },
  "triggers": [{ "id": "sunday", "during": { "days": ["sun"], "from": "08:00", "to": "23:00" } }],
  "bar": { "commands": [{ "name": "gameday", "description": "Show this space only on Sundays", "run": { "event": true } }] } }
```

```js
pistachio.bar.onCommand("gameday", async ({ spaceId }) => {
  await pistachio.storage.local.set({ space: spaceId });   // running it here is what gives the extension this space
  await apply(await pistachio.triggers.get("sunday"));
});
pistachio.triggers.on("sunday", apply);                     // main calls this when the answer is not the one it last heard
async function apply({ holds }) {
  const { space } = await pistachio.storage.local.get("space");
  if (!space) return;
  return holds ? pistachio.spaces.bringBack(space) : pistachio.spaces.sendAway(space);   // returned: a failure is tried again
}
```

No timer, no catch-up, no time zone, no restart handling: those are main's, and they are where an agent would otherwise ship the bug that only shows next Sunday. This is the fixture `extensions-triggers.spec.ts` runs, against a clock the spec moves.

## 7. Not done / open questions

- **The word.** *Away* and *Send away* are the working words; they live in `away.ts` and the shell's menu and tile.
- **Where a space comes back.** At the end of the rail, not where it stood.
- **Sync.** An away space is on this Mac alone and in no restore point this Mac publishes. A restore point applied here does not touch what is away, **nor bring it in again**: another device's, or an older one, may still hold that space under its id, and applied whole it would be here and away at once — brought back, the file's newer copy would be let go for the one "here already". So the space, the tabs its file holds and the tabs the restore point lists in it are left out as it is applied (`withoutAway`). An **archive entry** of an older copy is the same case by another road: restored "as itself", it would take the id of the space that is away. An id an away space goes by is not free (`createTabGroup`): the entry comes back a space of its own, under a new id, beside the one that returns.
- **The agent's own space.** A turn that sends away the space it is in goes on in a conversation nobody is looking at; the notice says what happened. Its answer is there when the space is back.
- **Window places.** The shell keeps each space's arrangement under the space's id, the last forty arranged (`pistachio.desk.v1`), and an away space's is not dropped: it comes back arranged as it was, unless forty others were arranged since.
- **A terminal in the space** ends as its tab goes, as at a quit. The person's own *Send away* is theirs to make; an unattended one is refused (§3.3).
- **A page no relaunch reopens** — a blank page, a `blob:` page, one whose address runs past 2,048 characters — keeps its space from going away, and from being closed by an extension or the agent, until that tab is closed (§2.2, *Every tab, or none*): neither the away file nor the archive has a place for it. The person's own *Close space*, and Tidy's own filing, are as they were: the archive keeps what it keeps of a tab.
- **Written by a live model.** Stage 2's gate was run with the extension as a fixture. `/extension show this space only on Sundays` with a real model writing it, reading its status and saying the schedule back has not been run.
- **The five seconds.** A press in one of the extension's own views (its panel, a page of its) makes the worker attended for five seconds: a trigger that lands inside them is not journaled and not held to the unattended list. Main cannot tell one handler's calls from another's once each has awaited. A command that has already answered lends a later trigger nothing.
- **One Mac.** What each trigger heard, the pauses and the journal are this Mac's, as away spaces are. Two Macs with the same extension each keep their own clock.
- **Notes with nobody there** wait for a journal line main can undo (§5, stage 5c). A tab may be opened then (§3.7); closing, showing and navigating one may not.
- **Every space's backdrop, on Home.** A theme for every space is drawn on Home too, where there is no space's menu to remove it from: the Extensions page's *Remove* is the way.
- **One mark drawn.** Two extensions marking one space both say so on the hover card; the tile draws the first.
- **Screenshots** lay the window's layers on one flat ground colour (`window-compose.ts`); a backdrop is in the shell's own layer, so it is in the picture, but the accent's tint of the ground is read from the nub's stand-in as before.
- **The accent and the Appearance page.** While a theme's accent is in force the Appearance page still shows and edits the person's own palette; nothing there says another accent is drawn.
- **A theme this Mac only**, as the rest is.
- **The journal's notice.** An unattended send or return is said in the window's notice and listed on the Extensions page; nothing else points from the notice to the page's Pause.
- **The band lies over a page's foot.** Like a live pill, a chip in the lane is drawn over whatever page reaches the desk's foot there — the page does not give way. One extension's six rows can run most of the desk's width. Nothing yet caps the lane's width short of the desk's, or lets the person fold a strip to its mark.
- **Rows refresh on an interval** (§3.6): `every … while` the window that shows them. Each refresh starts the worker (it does not stay), so a one-minute interval is a worker started every minute; nothing yet says so on the Extensions page, or counts what an extension's intervals cost.
- **An interval with no `while`** runs all day, every day. The sheet says *Every 5 minutes* and nothing warns that it never stops.
- **A worker the person started has a running worker's freedom.** For as long as it stays up — thirty minutes past its last use, longer while a page or its panel is open or it keeps calling — a worker's own timers call what its capabilities allow, with no handler in hand and so no unattended list: that was so before triggers, and a trigger is not use of it (§3.3). The list bounds what runs *because of* a trigger — a woken worker whole, a trigger's handler in a running one — it is not a sandbox around a worker the person just used.
- **The runaway rule is a count.** Eight acting runs of one signal's handler in two minutes pauses the extension; a flap slower than that — a space going and coming back every twenty seconds — is not caught, and is bounded only by the verbs' own rate limits. And it cannot tell a handler chasing its own tail from one keeping up with a person who really did open and close a call page eight times in two minutes: both are paused, and the notice says only what happened.
- **A calendar that never reads whole** — a ticked calendar that always fails, a ninth ticked calendar, one with more than fifty events in a day — leaves calendar signals not known for that person, with *The calendar could not be reached* on the Extensions page; the agenda's own limits (eight calendars, one page each) are the home page's, and a signal cannot say "no such event" from less than the day.
- **Held notices are the newest three.** What an extension did over a weekend is said as its last three things when somebody is back; the rest is in the journal, and nothing in the notice says there was more.
- **Idle, and the space in front.** Decided (§3.6, *Nobody there*): the handler of an `idle` or `screen` signal that holds may send away the space in front; no other trigger may. Idle is the system's — no key, no pointer — so a person watching something silent and still for ten minutes is "gone" to it; what is *playing* is still refused.
- **Events are this run's.** What happened while Pistachio was closed, the extension off or its triggers paused is never told (§3.7). Nothing on the Extensions page counts what was missed.
- **A download's event says only that one finished**: not its name or where it came from. There is no downloads API to ask; one would be a capability of its own.
- **A download's event is not proven end to end.** A download asks where to save through the system's own panel, which a spec cannot press: the rule for which downloads have just finished is unit-tested (`newlyFinished`), the wiring from main's hook is not.
- **Browser signals written by a live model.** As the stages before, 5b's gate was run with the extension as a fixture.
- **A page signal sees addresses, not calls.** "A Meet call is open" is a page on meet.google.com being open — its landing page counts. Whether a page holds the microphone or the camera is not something main reads today.
- **One calendar.** A calendar signal reads Google Calendar, as connected in Settings, in the Profiles the extension is on in; Pistachio's own reminders are not events to it, and there is no other provider. Nothing on the sheet says which Profiles' calendars that will be. Events are matched by a phrase of their name alone — not by calendar, guest or place. A calendar connected or disconnected is read at once; an event added in Google is seen within five minutes.
- **A signal's lag.** Power and displays are heard as they change; the network and idle at the next look, thirty seconds at most (five seconds for a return from idle).
- **Not known, and nobody told.** A signal that cannot be read says so on the Extensions page and in `triggers.get`; no notice tells the person that the stand-up extension has heard nothing since the calendar was disconnected.
- **Signals written by a live model.** As stage 2's gate, stage 5's was run with the extension as a fixture: a model choosing the phrase from "my stand-up" and saying which it chose has not been run.
- **No link rows.** Every press wakes the worker, which opens what it likes with what it was granted. A row that names an address for the shell to open would save the worker, and would let rows open any page: not built.
- **A mark on a tab** is drawn on its row in the sidebar only: not on a desk window's frame, not in the tab switcher. One mark a row is drawn; a second extension's is said in the tooltip. Nothing takes one tab's mark off from that tab's own menu: the Extensions page's *Remove* takes them all.
- **Marks for tabs that closed while no window was up** are not swept; they are bounded (two hundred an extension) and draw nothing.
- **The lane is the notch's.** Eight chips in all (`DESK_NOTCH_PILLS_MAX`), live pills first; a ninth is not drawn, and nothing says so.
- **Rows on this Mac only**, as the rest is.
- **Every space** is `spaces:all`, a High line of its own (§2.6). Nothing narrower exists between "the spaces I ran it in" and "all of them" — not "the spaces Tidy made", not "the spaces of this Profile".
- **Closed, and the archive lapses.** A space an extension closed is restorable for as long as the archive keeps entries (thirty days unless the person changed it), and its Undo with it. Nothing on the sheet says how long.
- **`byPerson` is one bit.** An extension is not told *why* a space is the person's (a name, a Stack, a conversation), only that it is.
- **A model's answer is not checked.** `ai.complete` hands back text; what an extension does with a wrong answer is bounded only by its other capabilities and the unattended list. It sends what the extension chooses, which the sheet says in one line and the ledger records as a size.
- **Usage is the account's.** A model call is counted with the rest of the person's AI usage, not under the extension's name.
- **One clock, five timers.** `main-clock.ts` is the one list of moments; each service keeps its own timer between them (§5).
- **Tidy is still built in.** The idle-space pass runs as an extension in the spec, with the built-in switched off there; shipped, the built-in is what runs (§5).

# Notes

A **note** is a document the person writes in Pistachio. Notes open in a tab at `pistachio://notes/<id>` as a blank page with a title and a body — no toolbar of heading buttons; the person types, and `#`, `-`, `[]`, `>`, ` ``` ` and `/` do what they do in Notion or Obsidian; every block has a handle that drags it and a menu that turns it into another. The body is **HTML-first** (N1): the document the editor keeps is stored as the HTML its schema writes, so a note can hold blocks markdown cannot — callouts, toggles, embeds, live HTML widgets — and markdown is kept beside it, derived, for everything that reads text: the agent, search, the clipboard, an older device. There is no save: every change is kept as it is made, every note lives in the account's end-to-end-encrypted workspace and follows the person to every device, and the agent reads and writes notes as first-class tools. `pistachio://notes` is the library.

Every section below is normative for the implementation on branch `notes`. Where a piece copies an existing one, the original is named and the copy follows it.

## 1. Decisions

| # | Decision | Choice |
| --- | --- | --- |
| N1 | Canonical format | **HTML, as the editor's schema writes it** — `<div data-type="callout">`, `<details>`, `<div data-type="embed">`, `<div data-type="html-block" data-html>`, and plain HTML for everything markdown has. The record holds that HTML in `html`, and beside it `markdown`, **derived** from the HTML by whichever host wrote the record (the editor sends HTML and main derives the markdown; the agent and a web editor send markdown and main derives the HTML). Markdown is what the agent reads and writes, what search and the snippet read, what "Copy as markdown" gives, what an older device still shows; a record from before HTML was canonical carries markdown alone and is completed on the way in (`completeNote`). Never editor JSON. The conversions run with no browser: `@pistachio/notes` parses and serialises HTML over zeed-dom, the same virtual DOM TipTap used for server rendering, so main, the cloud worker and the editor agree byte for byte. |
| N2 | One register per note | `note:<id>` holds `NoteRecord` — metadata **and** markdown in one sealed LWW register, like an artifact. No index register: readers list by prefix, and an index would be one contended key. |
| N3 | Images are sibling registers | `note-blob:<id>` holds one immutable, content-addressed image (`id` = first 24 hex of SHA-256 of the bytes). Markdown references it as `![alt](note-blob:<id>)`. Text and bytes never share a register, so autosave re-seals kilobytes, not megabytes. |
| N4 | Caps (client-enforced everywhere; nothing server-side stops growth) | `MAX_NOTES = 500`, `MAX_NOTE_TITLE = 200`, `MAX_NOTE_HTML_BYTES = 1_048_576` (a widget's source lives inside it), `MAX_NOTE_MARKDOWN_BYTES = 262_144`, `MAX_NOTE_BLOB_BYTES = 1_500_000` (after base64: ~2 MB, under `FRAME_BUDGET_BYTES`), `MAX_NOTE_BLOBS_PER_NOTE = 40`. The editor downscales a dropped image to ≤ 2048px on its long side and re-encodes (JPEG 0.85, or PNG kept when it has transparency) before it is ever stored. |
| N5 | Conflicts | Last-writer-wins by HLC, whole note — the sync layer's only merge (`mergeLww`). Two devices editing *different* notes never contend. The editor keeps typing local until idle; a remote version that lands while the editor is dirty is applied on the next idle save cycle *only if it is newer than what we last wrote* (see §5). No CRDT in v1; ProseMirror keeps the `y-prosemirror` door open. |
| N6 | Ids | Twelve lowercase hex, `randomBytes(6)`, like artifacts (`isArtifactId` regex reused as `isNoteId`). |
| N7 | Tool group | `user_notes` with tools `note_list`, `note_search`, `note_read`, `note_create`, `note_update`, `note_delete`. **Not** `notes` — that is the agent's per-run scratchpad (`task_notes`) and is stripped on answer turns (`runner.ts` `mode === "answer"`). Protocol request names are `note.*` singular (`notes.*` is the scratchpad's). |
| N8 | Shortcut | `newNote` = `Mod+Alt+N` (⌘⌥N). `openNotes` exists as a configurable action, default unbound. Appended **last** in `SHORTCUT_DEFINITIONS`. |
| N9 | Sharing | Read-only sharing reuses the artifact hosting pipeline: `hosted_artifacts` gains `kind ('artifact'|'note')`, routes `/v1/notes/:id/visibility|revision` and `/v1/public/notes/:shareId` copy the artifact ones, www proxies `/notes/<shareId>`. The published body is finished HTML rendered **on the owner's device** by `@pistachio/notes`; control never learns markdown. The page is served under `NOTE_PAGE_CSP` (`packages/notes/src/csp.ts`), not the artifact policy: an opaque origin (`sandbox allow-scripts …`) in which the note's own widgets run — each in the same `allow-scripts` `srcdoc` frame the editor shows, sized by the height it posts to the page's one script — and embeds are the editor's frames, with the web within reach (`script-src 'unsafe-inline' https:`, `img-src … https: http:`, `connect-src https: wss:`, `frame-src https:`) and nothing done as the site it came from (`form-action 'none'`, no same origin). Edit permission is a separate stage (§9). |
| N10 | Web | The notes pages are shell-drawn, so they run in `apps/web` once the cloud `ShellHost` answers `notes`/`onNotes` over `WorkspaceToolStore` and treats `pistachio://notes…` as a shell page. `apps/www` `/app/notes` is a read-only library + viewer over the decrypted workspace (like `/app/artifacts`). |
| N11 | Editor library | TipTap 3 (ProseMirror), pinned to one exact version across `packages/notes` (the schema) and `packages/note-editor` (the editor's surface, mounted by the desktop shell, the web shell and www alike), lazily loaded. No Lexical, no custom contenteditable, no `dompurify` (a closed schema is the sanitizer: HTML a record holds is parsed through it before it is shown, published or converted, and a widget's own HTML only ever runs inside a sandboxed `allow-scripts` frame with an opaque origin — a `srcdoc` frame wherever the page's own policy allows inline script, and from `pistachio-app://note-frame/` under `HTML_BLOCK_FRAME_CSP` in the desktop shell, whose page allows none: a `srcdoc`, `data:` or `blob:` frame inherits its parent's policy, so there a widget has to be served from an address of its own), no `shiki`, no `happy-dom` (zeed-dom, 500 KB and pure JS, is what runs the schema outside a browser). |

## 2. Records

`packages/sync-protocol/src/records.ts` (dependency-free, mirrored by `agent-runtime/src/views/notes.ts` and held together by `shell-contracts/test/record-docs.test.ts`):

```ts
export interface NoteRecord {
  id: string;             // 12 hex
  title: string;          // "" allowed; the library shows "Untitled"
  html: string;           // canonical body, as the editor's schema writes it; "" is empty; never includes the title
  markdown: string;       // derived from html by the host that wrote the record
  icon: string | null;    // one emoji, or null
  blobIds: string[];      // every note-blob this note references (for cleanup and caps)
  createdAt: string;      // ISO
  updatedAt: string;      // ISO
  revision: number;       // monotone, bumped on every local write
  source: { kind: "user" | "agent"; runId: string | null };
}

export interface NoteBlobRecord {
  id: string;             // 24 hex, sha256 prefix of the bytes
  mediaType: "image/png" | "image/jpeg" | "image/webp" | "image/gif";
  byteLength: number;
  data: string;           // base64
  createdAt: string;
}
```

`workspace.ts`: `NoteDoc {kind:"note", note}` and `NoteBlobDoc {kind:"noteBlob", blob}`; `workspaceKeyFor` → `note:<id>` / `note-blob:<id>`; both prefixes join `RECORD_KEY_PREFIXES`. A register holding `null` is a deletion.

`packages/agent-runtime/src/views/notes.ts` (Node-typed, the desktop's own type, dependency-free): `Note` (same shape as `NoteRecord`), `NoteSummary` (`Note` minus `html` and `markdown` plus `snippet: string` — the first ~160 chars of plain text), `NoteInput` and `NotePatch` (a body as `html` or `markdown`; `html` wins when both are given), the caps, `isNoteId`, `sanitizeNote` (a record without `html` is kept with `html: ""`, for a host to complete), `sanitizeNoteInput`, `sanitizeNotePatch`, `sanitizeNoteHtml`, `noteSnippet(markdown)` / `notePlainText` (an `html live` fence — a widget's source — is not prose, wherever it sits: behind a quote's or a callout's `>`, with backticks or tildes, in any case, to its close or to the end), `searchNotes(notes, query, {limit})` (title, then body, case-folded, ranked like `searchBookmarks`), `noteToolView(note)` (what the model sees: id, title, updatedAt, snippet or full markdown), `describeNote`, and `NoteEdit`. `packages/agent-runtime/package.json` exports `./notes`.

`packages/notes` (`@pistachio/notes`, pure, browser-safe and Node-safe) is the document itself:

- **Schema** — `noteExtensions({placeholder, overrides, extra})` and the cached `noteSchema()`: StarterKit (headings 1–3; H4–H6 import as H3), task lists (`@tiptap/extension-list`), tables with resizable columns, images (`src` is `note-blob:<id>`, base64 refused), and four nodes of its own under `src/nodes/`: **callout** (`div[data-type=callout][data-emoji]`, `block+`; markdown `> 💡 text`, GitHub `> [!NOTE]` alerts and `:::callout {emoji="…"}` import, Enter on an empty last line leaves it), **toggle** (`@tiptap/extension-details`, open state persisted; markdown `<details>`/`<summary>` HTML both ways; Enter at the end of an open title steps into its first line), **embed** (`div[data-type=embed][data-src]`, https only, YouTube/Loom/Vimeo/Figma resolved to their player URLs, a sandboxed iframe; markdown `<https://…>`), **htmlBlock** (`div[data-type=html-block][data-html]`, raw HTML run in an `allow-scripts` frame with an opaque origin; markdown an `html live` fence, a plain `html` fence stays code). Every node declares `renderMarkdown` — a test over `schema.nodes` enforces it, because a node without one vanishes on export. Also the Notion keys the stock keymap gets wrong (`keymap.ts`: Backspace at the start of a heading makes it text; a list's Backspace stops at the first list type that handles it; Tab never leaves the page; ⌘⇧↑/↓ move the block the caret is in, ⌘D duplicates it), the placeholder for the block under the caret (`placeholder.ts`: "Type / for commands", "Heading 1", "List", "To-do", "Toggle"), and the paste policy (`paste.ts`: plain text that looks like markdown is parsed, not quoted).
- **Conversions** — `dom.ts` runs ProseMirror's own parser and serializer over zeed-dom (`htmlToDoc`, `docToHtml`, `htmlToJson`, `jsonToHtml`, `jsonToDoc` with a repair round trip, `normalizeNoteHtml`); three members zeed-dom lacks are patched on its prototype there (`closest`, an iterable `classList`, `style.cssText`, a `setAttribute` that writes `"false"`). `markdown.ts` is `@tiptap/markdown` over the same schema (`markdownToDoc/Json/Html`, `jsonToMarkdown`, `htmlToMarkdown`, `looksLikeMarkdown`) with the readability passes botion's export had: empty paragraphs dropped, blank lines collapsed, `&amp;`/`&lt;`/`&gt;` back to characters where they cannot start markup, `[url](url)` as `<url>`, a GFM separator row as wide as its column, underline as `<u>` (the `++…++` the editor wrote before still imports, through its own inline tokenizer). Rules the review rounds of 2026-10-30 pinned: the tidy passes read a code span by its own delimiters (marked's rule, so `` ``a`b`` `` is one span) and see a fence behind a quote prefix or a callout's emoji (`> ```` is code, its entities and blank lines its own); a callout's marker is taken off its first line in the tokenizer before its blocks are read, so a callout whose first block is code, a heading or a list round-trips; a toggle looking for its `</details>` skips tags inside fenced code; frontmatter is dropped only when the fences hold YAML-shaped lines starting with a key (`---`, a paragraph, `---` are two rules and the paragraph stays); and `htmlToDoc` parses with `preserveWhitespace: true`, as the editor loads (`parseOptions`), so a run of spaces survives a structural edit and a reopening.
- **The agent's edit** — `applyNoteEdit(html, {mode, markdown, section?})` (`edit.ts`) works on the document's blocks: `append`/`prepend` add the parsed markdown's blocks, `replace` swaps them all, `replace_section` finds the top-level heading whose text matches `section` (case-insensitive) and replaces what follows up to the next heading of equal or higher level, refusing a heading the note does not have. Nothing else in the note passes through markdown.
- **Plain text** — `noteToPlainText(html)`, `jsonToPlainText(json)`, `noteWordCount`: a widget, an embed and code say nothing.
- **`completeNote` / `completeNoteBody`** — the half a record is missing, derived deterministically.
- **Publishing** — `renderNoteHtml(note, {blob})` → one self-contained HTML document (inline CSS in the shell's tokens, light/dark via `prefers-color-scheme`, blobs inlined as `data:` URIs, a picture by web address left as its address with `referrerpolicy="no-referrer"`, links `rel="noopener noreferrer"`) for `hosted_artifacts.public_html` under `NOTE_PAGE_CSP` (N9). The body is parsed through the schema first — the closed schema is the sanitizer — and written out node by node by `publish.ts`: a toggle is a native `<details>`, a to-do a disabled box, an embed the editor's sandboxed frame with its source as a link under it, a widget its own document (`buildHtmlBlockDocument`) in an `allow-scripts` `srcdoc` frame sized by the height it posts to `NOTE_PAGE_SCRIPT` — the page's one script, present only when the note holds a widget. Nothing the note held is written as a `<script>` outside a frame. A note with `html: ""` renders from its markdown. `csp.ts` holds the three policies (`NOTE_PAGE_CSP`, its `<meta>` form `NOTE_PAGE_META_CSP`, `HTML_BLOCK_FRAME_CSP`). Tests pin every one of those and the security rules.

## 3. Desktop store and sync

`apps/desktop/src/main/note-store.ts` copies `ArtifactStore`'s split: `<userData>/notes.json` (metadata, whole-file atomic rewrite), `<userData>/notes/<id>.html` (the canonical body) beside `<userData>/notes/<id>.md` (the derived markdown — what the agent reads, what a person can open in any editor; both read per request), `<userData>/note-blobs/<id>` (bytes, with the media type in the index). A note from before HTML was canonical has only its `.md`; it is completed the first time it is read, through `#servedBody`: when the derived HTML fits N4's cap its `.html` is written and the note is whole; when it would not (markdown within its own cap can grow fivefold as `&` becomes `&amp;`), the HTML is held in memory for this session's readers (`#oversized`) and never written or synced — every other device could only clamp it, and the person's own markdown is what survives; the editor still shows the note, and a save says why it cannot keep it as it is. `#readBody` is the body as stored and synced (`html: ""` for such a note); `get`, `edit` and search read the served one; a title-only `update` keeps the stored body and answers the served one. `#bodyFrom` refuses markdown whose derived HTML would not fit, as it refuses HTML over the cap. The cloud store does the same (`completeWithinCap`, `#storedNote` for a write that carries no body, `completeNote` on what it answers), completing each record once — a `WeakMap` keyed by the register's record, which is replaced whole on every change — so listing a library from before N1 converts it the first time, not on every record that moves. Surface:

- `list(): NoteSummary[]` (most recently updated first), `get(id): Note | null`, `search(query, limit)`.
- `create(input, source): Note`, `update(id, patch, source): Note` (bumps `revision`, stamps `updatedAt`, derives the other body form from the one the patch carries — HTML from the editor, markdown from the agent or a web editor — and recomputes `blobIds` from the HTML), `edit(id, edit, title, source): Note` (the agent's structural edit, `@pistachio/notes` `applyNoteEdit` on the HTML; a heading the note lacks is a thrown refusal), `remove(id)` (tombstones the note **and** every blob no other note references).
- `putBlob(bytes, mediaType): NoteBlobRecord` (hashes, dedupes, enforces `MAX_NOTE_BLOB_BYTES`), `getBlob(id)`.
- `onChange(listener: (snapshot: NoteSnapshot) => void)` — renderer-facing, **metadata only** (`{notes: NoteSummary[]}`), so a 500-note library never serialises bodies on a keystroke.
- `onRecordChange(listener: (kind: "note" | "noteBlob", id) => void)` — sync-facing, local writes only.
- `syncAll()`, `syncGet(kind, id)`, `applyRemote(kind, value)`, `removeRemote(kind, id)` — remote applies never echo back to `onRecordChange`; an identical value short-circuits; a record from a device that knew markdown alone is completed on the way in, deterministically, so its echo short-circuits too.

Wire it exactly as the artifact adapter is at `index.ts` (`new WorkspaceRecords({...})`): `"note"` and `"noteBlob"` join `WORKSPACE_RECORD_KINDS`, `recordDocFor`, `recordOfDoc`, `readRecordDoc` in `sync/workspace-map.ts`, and `WorkspaceRecords` in `sync/records.ts`. The global 40 ms publish debounce stays; the editor's own 600 ms idle debounce (§5) is what limits publish frequency.

## 4. Shell API and pages

`packages/shell-contracts/src/notes.ts`: re-exports the views, plus `NOTES_PAGE_URL = "pistachio://notes/"`, `NOTES_PAGE_TITLE = "Notes"`, `NOTES_PAGE_FAVICON`, `isNotesUrl(url)`, `notesUrlId(url)` (`null` = library, `string` = note id, `undefined` = not ours — the `briefUrlDate` convention), `noteUrl(id)`, and the request union:

```ts
type NoteRequest =
  | { type: "list" }
  | { type: "search"; query: string; limit?: number }
  | { type: "get"; id: string }
  | { type: "create"; input?: NoteInput }
  | { type: "update"; id: string; patch: NotePatch }
  | { type: "delete"; id: string }
  | { type: "putBlob"; mediaType: NoteBlobMediaType; data: string /* base64 */ }
  | { type: "getBlob"; id: string }
  | { type: "exportHtml"; id: string };
type NoteResponse =
  | { type: "list"; notes: NoteSummary[] }
  | { type: "note"; note: Note }
  | { type: "maybeNote"; note: Note | null }
  | { type: "deleted" }
  | { type: "blobId"; id: string }
  | { type: "blob"; blob: NoteBlobRecord | null }
  | { type: "html"; html: string };
```

`ShellApi` gains `notes(request: NoteRequest): Promise<NoteResponse>` and `onNotes(listener: (snapshot: NoteSnapshot) => void): () => void` (`IPC.notes`, `IPC.notesChanged`; `SHELL_METHOD_NAMES`, `SHELL_EVENT_CHANNELS`; preload; `ipcMain.handle` with `shellOnly`). The cloud host implements both in stage 2; until then it lists `notes` in `UNSUPPORTED` with a stub so `implements ShellApi` compiles.

`shell-pages.ts`: `ShellPage` gains `"notes"`; `shellPageOf` recognises `isNotesUrl`; `shellPagePlaceholderHtml` emits the title (`Notes`, or the note's title is set later by the page through the tab — see below) and favicon. **Tab title:** main sets it from the placeholder (`page-title-updated`), which is static. The editor therefore calls `shellApi().setTabTitle(tabId, title)` — a new, tiny `ShellApi` member (`IPC.setTabTitle`; desktop main sets `tab.info.title` and republishes; cloud sets `HostTab.title`) — whenever the note's title changes. Only shell pages may use it; main refuses it for a tab whose URL is not a shell page.

Commands (`chrome.ts` `ShellCommand`): `{type:"openNotes"; noteId?: string}` and `{type:"newNote"}`. Store (`store.ts`): `openNotes(noteId?)` selects an open tab at that URL or creates one; `newNote()` calls `notes({type:"create"})` then opens the new note. Chrome actions `openNotes` (label "Notes", `NotebookPen` icon) and `newNote` (label "New note", `shortcutId: "newNote"`), which makes them palette rows for free; add `ACTION_KEYWORDS` and `action-intents.ts` entries and a `SidebarMenu` item (`testId="notes-button"`). The palette also lists matching notes by title as `Saved` rows when the query matches (top 5, via `notes({type:"search"})`, debounced).

`ContentArea.tsx` `SplitPane` gains the third arm: `notesUrlId(tab.url) !== undefined` → `<NotesPage tabId noteId active />` (`React.lazy`, so the editor's chunk loads on first use).

## 5. The editor

**The surface is a package of its own, `packages/note-editor` (`@pistachio/note-editor`)**, free of any host: `NoteBlockEditor` (TipTap on the shared schema with the node views swapped in, the block handle, the slash and bubble menus, the link and image prompts, the keys; HTML in once, HTML out on every change, `show(html)` through its handle when the host has a newer version), `NoteTitle`, and `NoteEditorHost` — what the editor asks of the app around it, each optional with a meaning for its absence: `openLink(href, box)` (absent: a new context, no opener), `blobUrl(id)` (a note's own picture, at once or as a promise; absent: "stays on the owner's devices"), `subscribeBlobs(listener)` (the host's pictures changed, so a picture drawn as missing asks again), `uploadImage(file) → src | null` (absent: files are not taken and the Image row asks for an address only), `frameSrc(document)` (where a widget's document is served under its own policy; absent: `srcdoc`). Its files: `NoteBlockEditor.tsx`, `NoteTitle.tsx`, `host.tsx`, `SlashMenu.tsx` + `slash.ts` (the catalog, over `shell-contracts/fuzzy.ts`) + `slash-actions.ts`, `BubbleMenu.tsx`, `BlockHandle.tsx` + `BlockMenu.tsx` + `block-types.ts`, `LinkPopover.tsx` and `PromptPopover.tsx` over `RangePopover.tsx`, `pending-range.ts`, `image-src.ts`, `parts.ts`, `nodes/` (`CalloutView`, `ToggleView`, `EmbedView`, `HtmlBlockView` + `HtmlFrame`, `CodeBlockView`, `ImageView`; `nodes/index.ts` is the `overrides` list handed to `noteExtensions`), and `note-editor.css` — the whole `.note-*` sheet on the Geist tokens both the shell's theme and www declare, with `@source "."` so whoever imports it generates the utilities its components use. The desktop shell, the web shell and www mount the same component; `test/` covers the catalog and the prompts' arithmetic.

`packages/shell-ui/src/components/notes/` is the shell around it — `NotesPage.tsx` (routes library vs editor), `NoteLibrary.tsx`, `NoteEditor.tsx` (the bar, the title, autosave, and the shell's `NoteEditorHost`: links through `store.openLink`, pictures from `use-notes` `blobUrls`, files through the blob pipeline, and on the desktop `frameSrc: noteFrameUrl`), `ShareMenu.tsx` (stage 2), `parts.tsx`, `use-notes.ts` (its own zustand store like `use-brief.ts`: `summaries`, `bodies: Record<id, Note>`, `blobUrls: Record<id, string>`, `unsupported`, `error`, actions). Pure logic in `src/lib/notes-images.ts` (accept/downscale/hash), `notes-autosave.ts` (the state machine below, over the HTML), `notes-speech.ts` (read aloud, from the editor's JSON) — all covered by `test/**/*.test.ts` without a DOM. The document's shape is `@pistachio/notes`, never redeclared here. The desk's markdown file viewer (`components/desk/files/MarkdownViewer.tsx`) mounts the same node views (`noteNodeViews`, all but the picture's — a file's pictures are paths, not registers) under a `NoteHostProvider` of its own, so a callout, a toggle, an embed or an `html live` fence in a file is what it is in a note, the widget served by main on the desktop.

**Look.** `bg-background-200` page, `mx-auto w-full max-w-[760px] px-6` measure, a 52 px bar (back to library, breadcrumb of the title, `…` menu with Share / Copy as markdown / Read aloud / Delete — Read aloud speaks the title and body as prose, `lib/notes-speech.ts`, through the same player and media card as a page's read aloud, under the note's name). Title: an autosizing textarea (fitted again whenever its width changes) at `text-[40px] leading-[1.15] font-semibold tracking-[-0.03em]`, placeholder "Untitled", Enter moves into the body. Body: `text-[16px] leading-7 text-gray-1000`; H1/H2/H3 at 30/24/20 on the `text-heading-*` tracking; `hr` = `border-b border-alpha-300`; inline code on `font-mono bg-alpha-100 rounded-sm px-1`; code blocks `bg-alpha-100 rounded-lg p-4 font-mono text-[13px]`; quotes `border-l-2 border-alpha-400 pl-4 text-gray-800`; task items with the home page's tick; images `rounded-lg max-w-full` with a selected ring. Floating UI (slash menu, bubble menu) wears `bg-background-100 shadow-menu rounded-xl` with rows on the address palette's row measures (restated in the package's `parts.ts`); positioned with `@floating-ui/react` inside the pane.

**Extensions.** `noteExtensions` from `@pistachio/notes` (§2) with the node views swapped in, plus the editor's own: the pending-range highlight, the paste policy, the slash suggestion, ⌘K and ⌘↵. The editor is given `note.html` and reports `editor.getHTML()` on every change.

**Blocks, the Notion way (non-negotiable).**

- **Block handle.** `@tiptap/extension-drag-handle-react`'s `<DragHandle>` with nested handles on (`edgeDetection: "none"` and three rules: cells move with their table, a callout's or quote's first line is the block, a toggle's summary stands for the toggle) shows a "+" and a grip beside every block, nested ones included, vertically centred on its first line and clear of list markers (`measure`). The grip drags the block (the drop cursor is `.note-drop-cursor`); a click on it selects the block (`pending-range.ts`, block mode) and opens the **block menu** (`BlockMenu.tsx`: Turn into ▸ the shared `BLOCK_TYPES`, Duplicate ⌘D, Delete; arrow keys walk it, Escape returns the keyboard; it closes on any transaction that changes the document, since it holds the block's position as of when it opened). A toggle "turned into" another block is lifted first (`leavingToggle`: `unsetDetails`, caret on what was its title), so its title converts and its blocks follow as siblings. The "+" inserts a block below holding "/" — a sibling item in a list — so the slash menu opens on it. `.note-prose` pads a 56px gutter on the left and 40px on the right so both the handle and a widget's edit button stay inside the editable element, which is what keeps the handle from vanishing on the way to it; the column pulls the gutters back out (`-ml-14 -mr-10`) so the text still sits under the title.
- **Slash menu.** `/` at the start of a line or after a space, never in code; the query may hold a space ("heading 1"); grouped (Basic blocks, Media & advanced) while nothing is typed, one ranked list while filtering, each row with its markdown hint. Rows: Text, Heading 1–3, Bulleted, Numbered, To-do, Toggle, Quote, Callout, Code, Divider, Table, Image (a prompt at the caret for a picture's web address — `safeImageSrc`: http or https, a bare domain gets `https://` — with "Upload a file" beside it when the host takes files), Embed, HTML block.
- **Bubble menu.** On a non-empty text selection outside code: the block's name with Turn into ▾ (`BLOCK_TYPES`: Text, Heading 1–3, lists, Toggle, Quote, Callout, Code), bold / italic / underline / clear, then link / strike / code. Hidden while the link editor or the block menu has the selection.
- **Link editor.** ⌘K, or the bubble menu's link: a field over the range (`LinkPopover`), Enter applies (a bare domain gets `https://`), Open and Remove for a link that exists; the range stays highlighted while the field has the keyboard. `window.prompt` is gone. The highlight is cleared in a transaction of its own (`setPendingRange` keeps its transaction out of the history), so the link change stays undoable.
- **Keyboard.** The markdown input rules, `[]`/`[ ]` for a to-do, ⌘⇧↑/↓ and ⌘D on the block the caret is in, ⌘↵ ticks the to-do, Tab/⇧Tab nest and never leave the page, Backspace at the start of a heading makes it text, Enter on a callout's empty last line leaves it, Enter at the end of an open toggle's title steps inside.
- **Node views.** A callout's emoji opens a picker of presets; a toggle's chevron is a button (read only, it toggles locally); an empty embed is a field for the link, a filled one a sandboxed frame with its host and Open/Replace under it (the renderer's `frame-src` allows `https:` for this); an HTML block is its live frame, auto-sized by a height message from inside, with an Edit HTML button in the right gutter that opens a code field beneath (Esc or ⌘↵ closes it; Tab indents) — the frame holds its document as `srcdoc` wherever the page's policy allows inline script (the web shell, www), and on the desktop loads it from `pistachio-app://note-frame/?d=<base64url document>` (`shell-contracts/notes.ts` `noteFrameUrl` / `noteFrameDocument`), which main answers under `HTML_BLOCK_FRAME_CSP` with nothing kept between the two, because the shell's own `script-src 'self'` is inherited by a `srcdoc` frame and would run none of the widget (the renderer's `frame-src` names the origin); a frame loading inside the shell is not the shell reloading, so main's reload cleanup (the desk bridge, screenshots, live share) listens to `did-start-navigation` for the main frame rather than `did-start-loading`; a code block gets a language select and Copy on hover.
- **Placeholder.** Only the block under the caret says anything, and what it says is what it is.
- **Paste.** Image files go to the blob pipeline; plain text that looks like markdown is parsed as markdown.
- **Read aloud / Copy as markdown.** Both from the editor's JSON (`notes-speech.ts`, `jsonToMarkdown`): a toggle's title then its body, a callout's paragraphs; an embed and a widget are silent.

**Images.** Drop, paste or pick (`carriesFiles` / `clipboardData.files`, the `AgentConsole` pattern), through the host's `uploadImage`: in the shell, `notes-images.ts` refuses non-images and files over 20 MB before decoding, downscales per N4 on a canvas, hashes with `crypto.subtle.digest`, and the store calls `notes({type:"putBlob"})`; the editor inserts the answered `src: note-blob:<id>` and the object URL is cached at once so nothing flickers. Multiple files insert in order. A picture by web address (the Image row's prompt, or `![](https://…)` in markdown) is kept as its address and shown from it — the renderer's `img-src` allows `https:` and `http:` for this, as the published page's does.

**Autosave (`notes-autosave.ts`).** Pure state: `{local: {title, html} , saved: {revision, title, html}, dirty, inflight}`. Edits mark dirty and arm a 600 ms idle timer (also flushed on blur, on tab switch, on window hide, and before the page unmounts). A flush sends one `update` carrying only changed fields, then records the returned `revision`. A remote `onNotes` summary for this id with `revision > saved.revision`: if not dirty and nothing in flight, fetch and replace the editor content (selection kept by position when the doc still fits); if dirty, remember it and re-check after the next flush — by then our write has a later HLC and wins, which is N5, and the bar shows "Edited on another device" for 4 s so the loser is at least visible. Every host failure is swallowed into an `error` badge ("Not saved — retrying") with exponential retry; the page never blocks typing.

**Library (`NoteLibrary.tsx`).** "Notes" at `text-[34px]` with a `New note` pill, a search field (client-side over summaries, `Saved` group), then a list of rows — icon or a `FileText` glyph, title, snippet, relative time — sorted by `updatedAt`; an empty state with one line and the shortcut. Right-click / `…`: Open, Open in split, Copy link, Delete (confirm). Keyboard: ↑↓ Enter.

**Home teaser.** `components/home/HomeNotes.tsx`: the three most recent notes and "New note", mounted beside `HomeBrief` (hidden when the host refuses `notes`).

## 9. Sharing (edit)

The first cross-account authorisation in control, and a deliberate departure from E2EE for the shared body: the note's text is held on the server in plaintext, for exactly as long as a share stands, and every surface that offers a share says so in one sentence. It is the trade `public_html` already makes, made for named people instead of a link.

There is **no invite step**. A share names an account that already exists, by exact email, and is live the moment it is made — so `note_shares` has no pending state and no token, and a stranger cannot be reached at all.

**Control schema** (`migrate.ts` appended idempotent statements, mirrored in `schema.ts`, columns held together by `test/schema-parity.test.ts`):

- `note_shares (id uuid PK default gen_random_uuid(), owner_user_id → users cascade, note_id text CHECK ^[a-f0-9]{12}$, recipient_user_id NOT NULL → users cascade, role CHECK IN ('viewer','editor'), created_at, revoked_at NULL)`, `UNIQUE (owner_user_id, note_id, recipient_user_id)` and `CHECK owner ≠ recipient`, plus an index on `recipient_user_id` for the "shared with me" listing. A grant is never deleted: revoking stamps `revoked_at`, and every read filters on it.
- `shared_notes (owner_user_id, note_id, title, html, markdown, revision, updated_at, updated_by_user_id NULL, PK (owner_user_id, note_id))` — the body in both its forms (N1): the HTML the editor keeps and the markdown derived from it, `html` appended as its own idempotent `ALTER … DEFAULT ''` (a row from before carries `""` and is completed by whoever reads it, as a sealed record is; control completes nothing). HTML is capped at `MAX_NOTE_HTML_BYTES` (1 048 576), markdown at `MAX_NOTE_MARKDOWN_BYTES` (262 144) and the title at `MAX_NOTE_TITLE` (200), all **restated** in `app.ts` rather than imported, as `MAX_ARTIFACT_HTML_BYTES` is: a cap that drifts upward on a device must not widen what the server accepts.

**`noteAccess(userId, ownerId, noteId) → 'owner' | 'editor' | 'viewer' | null`** is the one helper in `app.ts` allowed to read a row whose owner is not `c.get("userId")`, and it is commented as such. Everywhere else authorisation stays structural (`eq(table.userId, c.get("userId"))`). A revoked grant answers `null`, which every route turns into **404**: a recipient whose access ended learns only that there is nothing there.

**Owner routes** (device bearer; anonymous accounts reach none of them — the `anonymousAllowed` allow-list):

| Route | Answer |
| --- | --- |
| `GET /v1/note-shares` | `{shares: [{noteId, id, email, role, createdAt}]}` — every live grant this account has made, so a Mac holding five hundred notes learns which two to keep current in one request. Its own path, not `/notes/shares`, which would shadow a note id. |
| `GET /v1/notes/:noteId/shares` | `{shares: [{id, email, role, createdAt}]}` |
| `POST /v1/notes/:noteId/shares {email, role}` | Resolves `users.email` (lower-cased, non-anonymous). **200 either way**: `{share: null, shares}` when nothing matched — no existence oracle — and `{share, shares}` when it did, upserting on the unique key so sharing again is how a role changes and how a revoked grant comes back. Sharing with yourself is `400 cannot_share_with_self`. Audit `note.shared`. |
| `DELETE /v1/notes/:noteId/shares/:shareId` | Stamps `revoked_at`, answers `{shares}` (the ones still standing), 404 for an unowned or already-revoked share. Audit `note.share_revoked`. **When the last live share goes, the `shared_notes` row is deleted** — the plaintext must not outlive its reason to exist, which is the `public_html` rule again. |
| `PUT /v1/notes/:noteId/shared {title, html?, markdown, revision}` | The owner pushes the body every share reads (`html` optional for a device from before N1; stored as `""`). `404 not_shared` when the note has no live grant, so a body is never stored without one; `{stale: true}` when `revision < held`; otherwise upserts (clearing `updated_by_user_id`) and answers `{stale: false, note}`. |
| `GET /v1/notes/:noteId/shared` | `{note: {title, html, markdown, revision, updatedAt, updatedByUserId} \| null}` — the owner reading back what an editor wrote. |

**Recipient routes:**

| Route | Answer |
| --- | --- |
| `GET /v1/shared-notes` | `{notes: [{ownerId, ownerEmail, noteId, title, role, revision, updatedAt}]}`, read by `recipient_user_id = me` so every row names the reader. `title`/`revision`/`updatedAt` are null until the owner's device has pushed the body once. |
| `GET /v1/shared-notes/:ownerId/:noteId` | `{role, note}` for a viewer or an editor, 404 otherwise. |
| `PUT /v1/shared-notes/:ownerId/:noteId {title, html?, markdown, revision}` | Editors only (`403 forbidden` for a viewer, 404 for a revoked one). `409 stale_revision` unless `revision > held`; on success stores `updated_by_user_id`. |

Tests: `test/note-shares.test.ts` — sharing with an existing and a non-existing email, a role change, revoke → recipient 404 **and** the plaintext row gone, a viewer's write refused, an editor's write read back by the owner, a stale write refused, cross-account isolation, anonymous 403.

**Owner's device** (`index.ts`, `account/control-client.ts`). `noteSharing: Map<id, {shared, mirror}>` is what this Mac believes: whether anyone is named on a note, and what control last agreed its body was. It is seeded by one `GET /v1/note-shares` on enrolment and on every poll, and corrected whenever the Share menu asks.

- Every local write that passes the existing `NOTE_PUBLISH_DEBOUNCE_MS` (2 s, one timer per id) also calls `pushSharedNote` beside `refreshPublicNote`, sending the title, the HTML and the derived markdown. A note nobody shares sends nothing. Nothing is sent when the mirror (title, html, markdown, revision) already agrees, so an untouched note is not re-uploaded every poll.
- A 30 s interval and `app.on("browser-window-focus")` call `pullSharedNote` for each shared note. A revision above this Mac's is applied as **the person's own write** (`update(id, {title, html}, {kind:"user", runId:null})` — or `{title, markdown}` when the body arrived as markdown alone, the store deriving the other half either way) — it is their note, edited by someone they named — so it seals, syncs to their other devices, and lands in an open editor like any other remote change. That write climbs past the shared revision, so it is pushed straight back and the two agree; the mirror is what stops the two chasing each other.
- `NoteRequest` gains `{type:"shares"; id}`, `{type:"share"; id; email; role}` and `{type:"unshare"; id; shareId}`; all three answer `{type:"shares"; shares: NoteShare[] | null; found: boolean}` — `null` on a Mac with no account, `found: false` only when an email matched no Pistachio account. `NoteShare {id, email, role, createdAt}` lives in `shell-contracts/notes.ts`.

**Share menu.** `ShareMenu.tsx` grows a "People" section under the link section: the list (email, a role select, a × to remove), an email field with a role and a Share button, a result line ("Shared with …" / "No Pistachio account with that email."), and the sentence that has to be there — *People you share with can read this note on the web; its text is stored on Pistachio's servers for them.* `use-notes.ts` gains `shares`, `loadShares(id)`, `share(id, email, role)` and `unshare(id, shareId)`, refusing through the same `refuse()` path as everything else.

**www.** `web-account/src/control.ts` gains `listSharedNotes`, `getSharedNote`, `putSharedNote` and `listNoteShares`, the body carrying `html` beside `markdown`. `/app/shared` is "Shared with me" (owner email, title, role, updated); `/app/shared/[ownerId]/[noteId]` mounts **the same editor the desktop writes with** (`@pistachio/note-editor`, §5): a viewer gets the document live and read-only — toggles open, widgets run in their `srcdoc` frames (the dashboard page carries no policy of its own), embeds play — and an editor writes it the way the owner does, every block and key the same, autosaving 1 s after the typing stops with `revision + 1`, the markdown derived from the HTML in the browser (`htmlToMarkdown`) before each save so an older device of the owner's still reads it, and showing "Saved" or "Someone else saved a newer version — reload." on 409. The session re-mints its token on its own, which refetches the note: a later answer is adopted — into the mounted editor through its `show` handle — only when it carries a newer revision and nothing of ours is waiting to go up; otherwise the save decides, by its 409. The markdown sent is clamped to its cap as every host clamps derived markdown (`sanitizeNoteMarkdown`), the HTML whole. The host it answers names only `openLink` (a tab of its own): no `blobUrl` — a share carries text, not the owner's sealed pictures, so each one is drawn as staying on the owner's devices — and no `uploadImage`, so the Image row asks for a web address only. A body that arrived as markdown alone (`html: ""`) is converted whole on the way in. `app.css` imports `note-editor.css` and names Geist's faces for it. Nav entry "Shared with me" in the `library` group. The owner's `/app/notes/[noteId]` lists who a note is shared with, read-only, and says that adding and removing people is done from the Mac — the body a share reads is pushed from there.

Deferred beyond this: invites to strangers, per-share key wrapping, sharing the pictures, realtime co-editing, comments, and sharing from the cloud host (the `notes` seam in `shell-host.ts` still refuses every sharing verb).

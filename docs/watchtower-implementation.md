# Watchtower implementation

Implemented on 2026-09-19. This records the desktop release of the [design](watchtower-design.md), including its deliberate limits. The original [draft](watchtower.md) remains a design reference.

## Use it

Open **Menu → Watchtower**, the top toolbar's Watchtower button, Settings → Watchtower → Open Watchtower, or `pistachio://watchtower`. How saving behaves — on/off, pause, this Space, what is sent to a model, excluded sites, the storage limit and retention, export, and forgetting by time or wholesale — is **Settings → Watchtower**, reached from the page's header or the address bar ("watchtower settings"). Forgetting one page or one site is on that page in Watchtower. Capture starts only after **Enable Watchtower**. Existing history is not imported retroactively.

Browse normally. Watchtower records eligible foreground visits, then extracts readable content after about a second of visible dwell. Search for distinctive words or a quoted phrase; combine them with `site:example.com`, `kind:video`, `after:2026-09-01`, and `before:2026-10-01`. Date filters use UTC. Results show the visit date and capture coverage. Select an observation, open its saved text, choose another version, or compare what changed. The address palette also offers up to three matching archived pages.

The active Space owns search, readers, links, deletion, and exports. Settings allow pause, domain/subdomain exclusions, excluding a Space, retention, a storage budget, agent access (off until chosen), Jev region filtering, Jev indexing, and optional enhanced search. The enable screen states the transfers — region excerpts to Jev, names and their sentences to Jev, retrieved text to the agent's model — as checkboxes before capture starts.

**Saved** (beside Timeline) is the pages saved on purpose with shift, shift — see "Saving on purpose" below; ⌘⇧B and `pistachio://bookmarks` open it on the desktop. **Index** lists what the saved pages are about — see "The index" below. Filter by kind, find an entry by any word of any spelling, open it for its facts and the pages that name it, follow either back to a saved page, and see a saved page's own entries under its title. The Watchtower button in the chrome shows its on-state while capture is recording, and says "paused" when it is not. Forget works by page, by site (with subdomains), for the last hour or day, for the Space, or for every Space. Disabling capture preserves the archive for reading. Domain exclusions affect future capture; use Forget to remove existing visits.

**Export Markdown** chooses a folder and writes a new `Watchtower-<timestamp>` directory: an index, one complete Markdown document per distinct snapshot, relative links/backlinks where the target was saved, one `entity-<id>.md` page per index entry (its kind and spellings as front matter, its facts and the saved versions that name it, linked both ways), and `visits.json` retaining every exported observation's provenance. Export uses a separate read-only utility process and a consistent database read transaction; search and capture continue in the writer process. Only one export runs at a time, with no 15-second RPC deadline. Changing archive settings or forgetting content stops an active export; a stopped export can leave partial files in its destination. Exports, conversations that already retrieved content, and device backups are separate copies.

## Storage and execution

- `packages/watchtower/src/archive.ts` owns SQLite, FTS5, compression, reconstruction, retention, garbage collection, and export.
- `apps/desktop/src/main/watchtower/worker.ts` runs that synchronous work in an Electron utility process, away from the browser main process.
- `apps/desktop/src/main/watchtower/service.ts` supervises the worker and coordinates bounded capture/RPC queues, visibility, navigation generations, privacy changes, and saved-reader responses.
- `packages/watchtower/src/regions.ts` decides which layout regions of a captured page are kept (see "What is saved"), `wire.ts` validates what the page returned, and `packages/agent-runtime/src/watchtower-filter.ts` asks Jev about the regions local evidence cannot settle.
- `packages/watchtower/src/capture.ts` runs a self-contained extractor in an isolated page world. It walks an explicit main region or a single article, falling back to the body when articles have siblings, and skips scripts, styles, navigation, forms, editable fields, hidden subtrees, and embedded frames. Visible password forms prevent content extraction. Metadata-only visits remain searchable.
- `packages/shell-ui/src/components/watchtower/` is the archive UI and `components/settings/sections/watchtower.tsx` its settings section. Both are built only from the shell's Geist tokens, type roles and `ui/` primitives (the page on the Bookmarks page's skeleton: header, recessed search strip, a timeline grouped by day, a reader pane beside it; settings on `Page/Group/Row/Block`); there is no Watchtower stylesheet. They share `use-watchtower.ts` (status, settings, forget, export, and the capture state the chrome button shows), `ForgetDialog.tsx` (the app's consequence dialog: what this does, what it does not), and `SavedText.tsx`, which renders saved blocks as text nodes only. The saved tab (`packages/watchtower/src/document.ts`) writes the same tokens out by hand, loads Geist from its own origin (`pistachio://watchtower/font/…`), and is tested against hostile page text.
- `packages/shell-ui/src/components/watchtower/WatchtowerPage.tsx` provides the archive page. Shared contracts also expose the feature on the web surface, where the host explicitly explains that the archive is desktop-local.

Visits are events; observations connect visits to immutable snapshots. A snapshot is an ordered manifest of SHA-256-addressed text blocks; hashes and digests are stored as 32 raw bytes, not hex. Blocks are compressed (raw deflate) only when that makes them smaller. A snapshot's identity is its text: links are not part of the digest, so a rotating "more stories" list under unchanged text is the same version. Links are stored once per snapshot as a compressed list, and each linked address once for the whole archive (`link_target`), which is what backlinks join on. A page is its address without an ordinary `#anchor` (hash routes keep theirs); the visit keeps the address as visited. Schema version 3; versions 1 and 2 upgrade in place at startup (hashes converted, links interned, both indexes rebuilt with the stemming tokenizer). Exact A → B → A content returns to the first snapshot, while repeated or reordered blocks remain reconstructible in their correct positions. There are no dependent delta chains. The comparison UI shows the changed region between two complete reconstructions.

A visit begins at committed eligible navigation, including same-URL reloads. Starting a navigation invalidates pending extraction without inventing a visit for a download, canceled navigation, or HTTP 204. Ordinary document anchors stay in the same visit. SPA path/query/hash-router changes settle for at least 500 ms before the next capture tick, with a five-second maximum wait on continuously changing routes. Same-document changes retain foreground dwell. Late page titles update metadata and its search index without changing captured snapshot titles. Returning to a tab after more than a minute away records a fresh visit. Short focus changes remain part of the current visit. Foreground content is reconsidered every 30 seconds; unchanged content adds no extra observation. A copied metadata-reader link remains valid after the first content capture completes.

The extractor yields between approximately 4 ms walk slices and stops at a 200 ms accumulated walk budget, a four-second wall-time check, 20,000 nodes, 1,500 blocks, or 192 KiB of body text. These are work limits, not a guarantee that an individual browser DOM/style call cannot take longer. Metadata and links have separate bounds. Main abandons extraction after six seconds and accepts at most 16 pending worker requests. Navigation, hiding the page, policy changes, and deletion invalidate stale results. Only human tabs with visible native views in the foreground window qualify. The tab an agent run is driving does not — the person's other tabs still do — and a page the agent loaded stays unrecorded after the run ends, until the person navigates that tab themselves.

The default storage budget is 2 GiB for the installation. Capture stops near the budget with a reserve for indexing/WAL overhead; this is a conservative admission budget, not an exact filesystem quota. Existing versions remain readable. Retention removes the saved text of old visits and keeps the visit — title, address, date, marked `expired` — so old history thins into ordinary history instead of vanishing; content no remaining visit references is collected. The UI warns at 90 % of the budget, before capture stops. Collection looks only at the blocks and link targets the orphaned versions used, never at every block in the archive; the remaining cost of Forget is FTS secure-delete itself (about a second per ten article-sized visits at 432,000 blocks), which is the price of the bytes actually leaving the index. Pruning runs at startup, periodically during ingestion, and hourly while idle. Deletion uses both core SQLite secure deletion and FTS5 secure deletion with original indexed text, followed by WAL checkpointing. It does not run whole-index optimization or VACUUM. Freed pages are reused and counted as reusable capacity rather than requiring a second database-sized file to compact. Committed privacy changes have no RPC deadline; worker exit still reports failure. The earlier contentless-delete schema upgrades its indexes once at startup. Space totals are cached between writes, while physical database/WAL usage is refreshed; the UI labels physical storage as covering all Spaces. Deletion reloads open saved readers and suppresses recapture of the still-open source until its next navigation.

## What is saved

The extractor drops only what can never be content: controls, hidden and screen-reader-only subtrees, live regions and meters (`aria-live`, `role=timer|progressbar|status|…`), the site's own `<header>`, and the video player with everything drawn over it — a bare playback clock ("0:00 / 18:39") never becomes a block, so a playing video no longer looks like a new version every thirty seconds. Consecutive list items and table rows are merged into one block, numbered when the list is; blocks with nothing to read ("| |") are discarded. Title, full description, creator, publication date and duration come from JSON-LD / microdata when the page declares them, so a video is findable by its channel and description even though the rendered description is collapsed. `kind:video` means the page declares a video or one dominates the viewport, not that an autoplaying ad exists somewhere.

Every block reports its place in the layout — a path of `tag#id.class` signatures with generated ids, hashed and state classes removed. `regions.ts` groups blocks into regions (a column of recommendation cards is one region, the article body another) and gives each one verdict:

1. A remembered rule for this host's layout (`rule` table; thirty days, 300 per host; holds signatures, never page text).
2. Decisive local evidence: the H1's region and the dominant region are kept; a block that announces itself as sponsored goes; a region under something named `related`, `sidebar`, `secondary`, `promo`… goes; one named `article`, `comments`, `description`… stays. On a page with a declared subject (article, video) a wall of links is never protected by its size; on an index page (mostly links, `kind: page`) links are the content and say nothing.
3. Everything else with a nameable signature is **asked of Jev**, once per site layout: up to 12 regions per call, each as its last three path segments, its share of the page, its link share, its block count and a 200-character excerpt — not the page, not the URL. Jev answers a role per region (`main_content`, `about_content`, `discussion` are kept; `recommendations`, `advertising`, `site_chrome` are not) with a calibrated confidence. Below 0.6 the text is kept. Both outcomes are remembered, so the next page of that layout costs no call and — which revisit deduplication depends on — extracts identically.

Doubt keeps text: an unnamed wrapper is never dropped, a failing or absent model keeps the local guess and rests for a minute per host, and verdicts that would discard most of a page without keeping its headline are not believed. Excluded hosts, password pages and agent-loaded pages never reach this step. With the setting off, capture makes no network request and relies on steps 1–2.

Measured on live pages (2026-09-19, same pages before and after): Wikipedia's first save 102 KB → 57 KB; a YouTube watch page 24 KB → under 8 KB with the clock, the merch shelf and the recommendation rail gone, and a revisit 32 KB → 0; The Verge's front page no longer gains a version when an ad loads. `packages/agent-runtime/test/watchtower-filter.live.test.ts` (`PISTACHIO_WATCHTOWER_LIVE=1`) checks the criteria wording against the real model: six of six regions, ~0.7 s.

After the first capture a passive `MutationObserver` counts substantial added text (40+ character insertions; never character data, so clocks and counters do not register). The host reads that one number before looking again, skips the walk under 400 characters, and backs off 30 s → 60 s → 2 min → 5 min. A visit keeps at most 12 observations.

## The index: pages become objects

A page is a document; what it is about persists across sites. Stripe's pricing page, a TechCrunch story and a podcast transcript all describe one company, so the index holds one entry for it with three sources, and the archive reads as "117 companies, 64 people, 23 technologies, 16 projects and 31 questions" as well as 4,823 visits. Nothing is replaced: saved versions stay the record, and every entry, mention and fact points back to the version it came from.

**Primitives.** An entry is one of eleven kinds (`WATCHTOWER_ENTITY_KINDS`): person, company, organization, product, technology, place, event, work, project, concept, question. A **fact** is a sentence a page wrote about an entry, kept verbatim and sorted as what it is (`definition`), a number (`metric`), a `price`, something that happened (`event`) or a `claim` — never a summary, because Jev writes nothing. Pricing plans, claims and metrics from the original sketch are facts about an entry rather than entries of their own.

**Storage** (schema version 4; version 3 upgrades in place): `entity` (Space, kind, display name), `entity_alias` (every spelling, stored once per normalized key — "Stripe, Inc.", "Stripe’s" and "stripe" are the key `stripe`), `mention` (entry × saved version: count, salience 0–1, the sentence it was named in), `fact`, and `entity_ignore` (names a person removed, kept out). Mentions and facts cascade from their snapshot; an entry nothing mentions is deleted in the same `collect()` that removes orphaned blocks, so Forget, retention and Space deletion take what was learned from a page with the page. `snapshot.understood` records how far a version has been read (0 not yet, 1 locally, 2 by the model) and `snapshot.subjects` what the page declared about itself.

**Finding names** (`packages/watchtower/src/entities.ts`, local and deterministic). Runs of capitalized words in sentence-case prose ("Patrick Collison", "Bank of America", "iPhone 16", "AT&T"), with the sentence start, interface words, dates and Title Case headlines discounted; a lone capitalized word counts only where the page capitalizes it mid-sentence more often than it writes it plain, or the title names it. The title is read for its subject between the site's own name and a slogan ("Patrick Collison - Wikipedia"; the site signs are learned per host from its other saved titles). A page's own abbreviation ("Y Combinator (YC)") and a surname used after the full name become aliases. Structured data settles kinds without a model — a declared `Product` is a product, its `brand` a company, an `Event` an event; the capture script now sends these as `subjects` (at most 12, validated in `wire.ts`). A GitHub/GitLab address is a project; a search engine results page is a question — what was searched, not the snippets on it. At most 24 names per version, most central first, and at most 8 candidate fact sentences (a definition, a number or a date near a name, attributed to the longest name the sentence gives first).

**Two passes.** Exclusions are applied in the query that picks pending versions, before its limit, so versions of an excluded site never stand in front of eligible ones, and they are not counted as pending. At capture, only what the page declares is filed (`understood=1`), with no model and no prose parsing — capture p95 is unchanged. Afterwards, when **Index people, companies and ideas with Jev** is on (`smartIndex`: off until chosen, so an archive enabled before the index existed never sends anything; on by default in the enable screen), the service reads one pending version at a time, newest first (`EntityIndex.next`), asks Jev, and writes the answer (`understood=2`). Versions with nothing to ask are completed locally on the way. Excluded sites and Spaces are never offered. The loop runs only while saving is on, unpaused and below the storage limit; rests a minute when nothing is pending (a capture wakes it two seconds later) and a minute after a model failure; and discards an answer when a Forget, a settings change or a hand edit happened while it was being made. Versions saved before the upgrade are filed locally in the background.

**What Jev is asked** (`packages/agent-runtime/src/watchtower-entities.ts`, at most two parallel requests per version): for each undecided name (≤ 16), a choice among the kinds or `not_a_name`, judged from the name and its sentence; for a name that may already be in the index (same spelling in any kind, or one name inside the other — "Collison" and "Patrick Collison"), which known entry it is or `new` (≤ 8 questions, ≤ 4 entries each, each described by kind, spellings, sites and one example sentence — never an id); for a search, whether it was to learn something or to reach a site ("gmail" is not a question); for each candidate sentence, what it says or `nothing_specific`. State holds the host, the title, names, sentences and those descriptions — no URLs, no page. **Doubt creates nothing**: below 0.5 confidence a name stays out of the index (the page is still saved and searchable); below 0.6 a match makes a new entry instead of merging — a duplicate can be merged later, a wrong merge hides a page. An answer out of shape fails the whole version, which stays pending. An entry of the same kind and spelling joins without a question.

Measured on 2026-09-27 against the live gateway (`PISTACHIO_WATCHTOWER_LIVE=1 pnpm vitest run test/watchtower-entities.live.test.ts` in `packages/agent-runtime`): a funding story's 11 names — company, founder, investor, product, technology, place, event, concept, and two interface labels — all sorted correctly, "Stripe" matched to the existing entry and not to Stripe Press, a surname shared by two people left unmerged, four sentences sorted as definition, price, event and nothing; six searches told apart (investigations vs "gmail", "facebook login", "nytimes"). About 460 ms per version.

**Normalizing by hand.** An entry offers "Possibly the same as" for same-kind entries whose names contain one another; **Merge** moves its pages, facts and spellings into the other. **Kind** corrects what it is. **Remove from index** deletes it and keeps its spellings out of the index for that Space (dropped when the Space's archive is emptied). Saved pages never change.

**Retrieval.** `entities` (by kind, and by any word of any spelling from its start) returns entries with page, site and fact counts, first and last visit, per-kind counts and how many versions are pending; `entity` returns facts with their source observation, the pages that name it with the sentence, sites, related entries (named on the same versions) and merge suggestions; `read` lists a saved version's entries. The agent gets `watchtower_index` and `watchtower_entity` beside search and read, under the same agent-access setting and Space binding; entry names and facts are marked untrusted evidence in-band.

Limits: capitalization is the only signal for names in prose, so text without it (CJK, all-lowercase) contributes only declared subjects and searches, and German nouns cost questions that end as `not_a_name`. Pronouns and "the company" are not resolved to the entry they refer to. Near-match lookup scans aliases with `LIKE` per token — fine at thousands of entries, not designed for millions. An entry's kind is decided when it is created; later disagreement shows up as a second entry to merge.

## Saving on purpose (shift, shift)

On the desktop, bookmarks and Watchtower are one feature. Tapping shift twice on a page (or **Save this page**, the command palette, or **Add** with the page open in a tab) saves it in two places at once:

- **The saved record** — the card: the thing the page is about, its facts, keywords and your note. It is the synced bookmark record, so it still reaches the person's other devices and the web app's Bookmarks page, which are unchanged.
- **Watchtower** — the page's full text, kept now whatever passive capture is set to (off, paused, never enabled): the save is the person's say-so for that page. The page is marked kept (`page.kept_key`, the saved record's address key) and retention leaves its text for as long as a saved record with that key exists; deleted here or on another device, the page ages like any other. An excluded site or Space, a page with a password field, and a tab the agent is driving are not kept; the save itself still stands and the card says why. Jev filters the page's regions only if Watchtower is on and its filter allowed.

One reading by the language model (the agent's model; **Read saved pages with the model**, formerly Bookmarks' "Ask the model", governs it) fills the card AND names everything the page is about: a profile is the person and their company, a review the product and its maker, a funding story the company, its founders and its investors (`bookmark-extractor.ts`, at most 12). Each entity comes with a kind from the index's primitives, a role (`subject`, `major`, `mention`) and up to four facts, each a sentence the model must copy from the page; a quote not found in the page's text — after whitespace and typographic quotes are normalized — is dropped, so a fact is still always something the page said. The entities are filed under the kept version (`EntityIndex.prepareSaved`, level 3): an entry of the same kind and spelling is joined; a name that may be another entry ("Collison") is put to Jev as a match question when the index's Jev setting allows, otherwise it becomes its own entry with a merge offered. This reading is MERGED with what earlier passes found on that version and is never replaced by the passive Jev pass: a passive result that finishes after the save (it was still asking Jev) is refused rather than allowed to erase it. The filing is bound to the observation the save kept and the policy epoch it was kept under — the reading arrives seconds later, and a page forgotten meanwhile may already have handed its version's id to another page, in any Space — so after a forget or settings change, or when that observation no longer holds the version, nothing is filed. A deliberate save is not held to the passive dozen observations per visit, and a save that could not be written (storage full, a capture too large) is reported as not kept, never as the previous version. Saving a page already saved saves it again — a new version if it changed, its card refreshed where you have not edited it, its entries brought up to date.

The card shows the Watchtower half on its last line: "Keeping in Watchtower…", then "Filed under" with the entries (each opens its index entry), or why the page was not kept. In Saved, an item's detail says what the page is filed under and opens its saved text. On the desktop, Settings → Bookmarks is folded into Settings → Watchtower ("Saving on purpose"); the web keeps its own.

Measured on 2026-09-27 with the agent's model through the live gateway (`PISTACHIO_WATCHTOWER_LIVE=1 pnpm vitest run test/bookmark-extractor.live.test.ts` in `apps/desktop`): a founder's profile yielded the person as subject, her company, her co-founder, the product, a former employer, the lead investor and a concept, each fact a sentence of the page; about 5 s, the same call that fills the card. A save by address with no open tab, and the agent's saves of an address, fill the card only.

**The gesture.** The double-tap detector (`shell-contracts/src/double-shift.ts`) no longer depends on seeing every key release. When main consumes a key-down in `before-input-event` — any app shortcut pressed on a page, ⌘=, ⌘L, ⌘R — Chromium swallows that key's key-up and the key-ups after it until the next key-down, so main never saw them; the detector kept those keys "held" and refused every later tap until the window lost focus. Other modifiers are now read from each event's own flags and another key counts as held only while pressed or repeating (1 s without a key-down ages it out). `e2e/tests/bookmarks.spec.ts` presses ⌘= on the page and then taps; that step fails against the previous detector.

## Retrieval and Jev

Normal search is local, with bounded term/phrase syntax and Space/time/site/type filters. Results are ranked: per word, the best-matching block's BM25 (FTS5's `rank` column — the `bm25()` function cannot be used under a join), summed across words, plus a bonus for words in the title and a small recency term, so a page about the words outranks a newer page that mentions them. The index is stemmed (`porter unicode61`), so "blight" finds "blights". The word still being typed completes as a prefix unless it already is a word the archive knows. A word present in more than a quarter of all blocks is dropped beside a more telling one. Date windows are pushed into the index as a rowid range (block ids are chronological), and a query made only of near-universal words is matched against recent content. At 432,000 blocks: rare, prefix and mixed queries 11–17 ms, a lone common word 79 ms, a date-windowed common word 67 ms. Terms can match across different blocks of a snapshot; phrase verification spans block boundaries and paginates verified matches. Metadata-only visits have their own small FTS index. Query and phrase tokenization use SQLite’s actual unicode61 tokenizer through a memory-only temporary index. Phrase verification reuses decisions for identical snapshots and stops explicitly after 500 distinct candidates, 16 MiB of reconstructed candidate content, 10,000 observations, or a one-second verification budget. An overly broad phrase produces a request to add filters rather than silently incomplete results. Temporary worker failures return a retrying 503 saved reader; only missing or cross-Space observations return 404. Search resolves the matching historical observation, not just a page's latest content.

Enhanced search is off by default and runs only when the person clicks **Improve matches** after enabling it. Local candidate generation broadens the keyword match, then `packages/agent-runtime/src/watchtower-rerank.ts` asks the existing account-backed evaluation model to score at most 20 titles and short excerpts. The default configured decision model is Jev. IDs, URLs, timestamps, and full documents are not included in the decision state. The query, titles, and excerpts can themselves contain private content; the UI makes this transfer explicit. The result can reorder existing observations only. Timeout or invalid output leaves local candidates available. Capture itself calls a model only for region filtering, as described above, and only when that setting is on; the index reads saved versions afterwards, and only when its own setting is on.

Agent access is **off by default**. The agent receives `watchtower_search` and `watchtower_read` only through a Space-bound host when archive access is allowed and capture is enabled or that Space has saved history. A never-enabled empty archive registers no tools. Each call rechecks permission; reads return at most 20,000 characters with continuation offsets and visit provenance. Retrieval is explicit and recorded in the ordinary tool trace. Archived text is identified as untrusted evidence rather than instructions, in the tool descriptions and in-band in every tool result. Retrieved text can be sent to the agent's configured model.

## Limits

This is a text archive of content available in the rendered page. It does not record pixels, media binaries, inaccessible frames, canvas content, OCR, video/audio transcription, or content that requires opening a hidden transcript. Video recall uses available page titles, descriptions, creator information, and rendered text. Large or busy pages can produce partial captures; brief or excluded-from-extraction visits can contain only URL/title metadata.

Search currently uses lexical retrieval, with optional decision-model reranking; there is no local vector index or trained capture classifier. The first UI returns 50 visits per page and up to 100 observations in a page's version selector. A full export retains all observations. Comparisons identify the changed block region rather than a minimal word-level diff.

The archive is stored at `<userData>/watchtower/watchtower.db`, outside the synced workspace registers. It is not encrypted by the app. Cloud capture, cross-device archive sync, richer media adapters, and app-level archive encryption are not part of this implementation.

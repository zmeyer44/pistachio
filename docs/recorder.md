# Recorder

The **Recorder** is the first extension in Pistachio's library (docs/extensions.md §9, X13): a screen recorder in the style of screen.studio for the browser. It records a desk window — the page's own pixels, crisp at twice the view's size, with the page's sound — and what the person did in it (where they pointed, what they clicked, where they typed), and then polishes the recording in an editor: a camera that zooms to the thing clicked and follows the cursor on a spring, a cursor redrawn large and smooth with click ripples, idle time sped up, a background with padding, rounded corners and a shadow; and exports an MP4, a WebM or a GIF. It is built only on the public `pistachio.*` API: whatever it needs that the API lacks, the API gets (the dogfood rule).

Desktop only. `apps/desktop/extensions/recorder/`, id `com.pistachio.recorder`, bundled with the app (`Resources/extensions/recorder/`). Every section below is normative for the implementation on branch `extensions`. What was measured on Electron 43.4.1 (M4, 2026-10-30) is marked so.

| Piece | Where |
| --- | --- |
| Manifest | `apps/desktop/extensions/recorder/pistachio.json` |
| The worker (the engine) | `worker.ts` → `src/engine/` (capture, encode, events, the project on disk) |

## 1. Decisions

| # | Decision | Choice |
| --- | --- | --- |
| R1 | **A window, through tab capture — and the pages after it.** | `pistachio.capture.tab(tabId, { audio: true, scale: 2, frameRate: 60 })` in the worker: no macOS permission, 58 fps and a 133 ms start (measured), the page's sound in stereo (echo cancellation, noise suppression and gain control off, else it is processed mono — measured), twice the view's size even on a 1× display (the page renders at device-pixel ratio 2 meanwhile and for ~800 ms after; the countdown hides the swap). The recording **follows the person** (2026-11-03): whichever page comes in front while it runs — a tab chosen, a window clicked, a page opened beside — is captured from then on (`tabs.onActivated`, a feed per tab, one `screen.mp4`), so the clip shows every tab they visited; main lets the extension capture the tab in front while it records (docs/extensions.md §5). The whole Pistachio window, another app, the screen: not in v1 (a native ScreenCaptureKit module with the cursor off, later). |
| R2 | **Record raw, compose later.** | The raw screen is H.264 High, a keyframe a second, fragmented MP4 written to disk as it is encoded (a crash loses a second), the mic AAC in its own file, the camera H.264 720p30 in its own, events in `events.jsonl` flushed every 250 ms. Nothing is composed while recording. mediabunny 1.61.6 (MPL-2.0, pinned) muxes; WebCodecs encodes (H.264 and HEVC in hardware to 4K60, AAC and Opus — measured). No ffmpeg, no utility process. |
| R3 | **One `render(tOut)`.** | A pure function of output time draws a frame from the project: time map → background → shadow → the content quad under the camera transform with rounded corners → the cursor sprite → the camera bubble. The editor's preview and the export call the same function (Canvas2D in v1: 0.10 ms a frame at 1080p measured; WebGL later for motion blur and SDF corners). |
| R4 | **The solvers see the whole timeline.** | Zoom segments, the camera path, the cursor path and the speed plan are pure functions over all the events, run on open and whenever an edit changes their inputs; a 10-minute recording solves in milliseconds. The camera arrives before a click (a 350 ms lead) because the solver knows it is coming. |
| R5 | **"Natural" cursor in v1.** | Chromium draws the system cursor into a tab capture while the mouse moves over the page and ignores `cursor: "never"` (measured). The cursor layer draws a vector cursor at the *raw* pointer position, the same shape (`cursor` events), size ≥ 1, so it covers Chromium's exactly: ripples, size and zoom all work; the smoothing slider is drawn disabled with "needs a newer Pistachio". Smooth and Glide modes are coded behind it for the day the host hides the cursor from the capture. While the cursor is baked in (`cursorBaked` true, every v1 capture), the editor locks Smooth, Glide, Hidden and Hide when idle (`lib/cursor-modes.ts`): they would draw a second cursor or hide the drawn one while the recorded one stays. |
| R6 | **The editor is a desk window.** | `pistachio.ui.openPage("editor", { query: "rec=<id>" })`: a page of the extension, a window on the desk of the space the recording was made in, filling it; never a modal. It never touches the recorded tab. |
| R7 | **Where things live.** | A recording is a folder in the extension's data root, `recordings/<id>/` (`files.data`, `<id>` = `2026-10-30T15-04-12`), holding `screen.mp4`, `mic.m4a`, `camera.mp4`, `events.jsonl`, `mic.levels`, `thumb.jpg`, `project.json`. Exports go to the screenshots folder through `files.save(…, { folder: "screenshots" })`, named `Screen Recording 2026-10-30 at 3.04.12 PM.mp4`. Raw recordings are never synced. |
| R8 | **Kept out of the picture.** | The status pill (`ui.setStatus`), the count of three (in the pill), the Bar, the sidebar, notices: tab capture is of the page alone, so none of it is ever recorded. ⎋ never stops a recording. |

## 2. What a person does

**Start.** The Ledge icon opens the panel: the source (the window in use, chosen; *Another window ▸* lists the desk's windows with their stills from `capture.sources()`), the mic (a device menu and a live meter), the camera (off by default; a bubble preview when on), *Page sound* (on), *Quality* (Crisp 2× · 60 fps, or Native · 30 fps), the countdown (3 s), and **Record**. `/record` in the Bar records the window in use with the last choices; `/record desk` is refused in v1 with "the whole desk arrives later". ⌘⇧6 (the manifest's `commands`) starts on the window in use and stops a running recording. *Record this window* on a desk window's ⋯ menu (`contextMenus`, `window`).

**While recording.** The status pill beside the Bar's nub: `● 0:42 ▁▃▅ ⏸ ■` — a red dot, the clock, a four-bar mic meter, pause, stop; its menu (⋯): *Discard*, mic and camera toggles. It lies in the nub's lane (docs/extensions.md §5, `ui.setStatus`), so the recorded window under it stays live: the person uses the page, and every `box` says `visible: true`. (Until 2026-10-30 the pill was a desk cover, and the window under it went still for the whole recording: a click landed on the shell, the cursor path hid the cursor, the export had none.) `/record` from the Bar puts the Bar's field away as it runs, so its pill is not left out over the page either. The recorded window shows a 2 px red ring (not in v1 if the API lacks a window mark; the pill names the window instead). The tab is held (`capture.hold`): never archived, slept or re-zoomed.

**It follows the person.** Whichever page comes in front — a tab chosen in the sidebar, a window clicked on the desk, a page opened beside — is recorded from then on, with its sound, and the pill names it: one clip of every tab visited. The new page's input says where its view is and what it shows (a `box`, a `nav` at the switch), so chapters and the zooms follow, and the browser frame's address with them. A shell page in front — Home, the notes, the extensions page, an extension's own page — is never recorded: the picture holds on the last page (its last frame, at the frame rate) until a page is in front again. The page the recording began on is let go once the next one shows (its capture stopped, its hold released); a page that will not open — a private address, a renderer mid-navigation — is tried three times, then a notice says the recording stays where it was. Free space is checked before starting (warn under 5 GB, refuse under 1 GB) and watched (auto-stop and finalize under 1 GB).

**Stop.** The pill's ■, ⌘⇧6, `/stop`, or the panel. The files are finalized, a thumbnail is taken, `project.json` is written with the auto zooms, speed plan and the default look, and the editor opens on it. The panel's *Recent* lists the last five recordings with their thumbnails (open the editor, reveal, delete).

**Edit.** The editor (§5): a preview with transport; a timeline with lanes — chapters (from `nav` events), clip (cuts), zoom (auto segments dashed until touched), speed (amber, "4× idle"), events (clicks, ⌨ bursts, ↕ scrolls), mic; an inspector — Background (wallpapers, gradients, a solid, a blur of the page), Frame (padding, corners, shadow, window chrome: browser · mac · none; aspect 16:9 · 9:16 · 1:1 · 4:3 · fit), Cursor (mode, size, click effect, hide when idle), Zoom (auto on/off, feel: Quick · Mellow · Slow, max level), Camera (shape, size, corner, shrink on zoom), Audio (mic, page, mute while sped up). Keys: Space, ←/→ a frame, ⇧←/→ a second, J/K/L, **S** split, ⌫ delete the selected range, **Z** add a zoom at the playhead centred on the cursor, **X** a speed segment over the selection, ⌘Z/⌘⇧Z. Selecting a zoom shows its rectangle on the preview: drag to re-aim, resize to change the level.

**Export.** The button opens the sheet: format (MP4 H.264 · MP4 HEVC · WebM · GIF), size (720p · 1080p · 1440p · 4K, greyed above the source × 1.25), fps (30 · 60), quality (Standard · High · Studio), destination (Screenshots folder · Copy · Add to a note). Progress and an ETA in the sheet; the engine runs it (§5), so the window may close — Back, the tab's ×, the window — and the export goes on to the end, its destination and its notice. One export at a time: a second, from any editor, is refused with a sentence while one runs. A two-minute 1080p60 export takes 40–60 s on an M4 (measured pipeline: 203 fps). GIF: 960 px wide, 15 fps, ≤ 20 s, one palette. Done: the chosen destination (the Finder shows it, or it is copied, or a new note links to it), a notice *Exported · Show in Finder*, and the finished card in the editor — or in the editor opened again on the recording — with a looping muted preview, *Copy* (`clipboard.write({ filePath })`), *Reveal*, *Add to a note* (a link line, until notes have a video block; with nothing saved, the name alone, never a link to nowhere), and the thumbnail draggable out (`files.startDrag`). An export that could not be saved is neither copied nor noted: a notice says why. The export is written into the extension's data (`exports/<name>`) and saved from there to the screenshots folder (`files.save`); that copy, which the card's preview plays and its drag hands out, is removed once the card goes — dismissed, or a next export begun — and only when the save succeeded (unsaved, it is the only copy). Closing the editor keeps it, for the card when the editor opens again; the engine remembers it in `storage` (`exportFinished`), so at most one lingers. Until 2026-10-30 every export left one there; until 2026-11-02 the editor's window ran the export, and closing it killed it.

## 3. The engine (the worker)

```
worker.ts
 ├ bar.onCommand("record") · commands.onCommand("toggle") · contextMenus.onClicked("record-window") · runtime.onMessage (the panel's Start/Stop/options)
 ├ session: { id, startedAt, t0, state: "counting" | "recording" | "paused" | "finalizing" }
 ├ feeds (follow.ts): one per tab in front — capture.hold(tabId) · pistachio.capture.tab(tabId, { audio, scale, frameRate }) → MediaStream · input.subscribe(tabId)
 │   tabs.onActivated(a web page) ─► the next feed is opened (3 tries, 300 ms apart); its first frame takes the picture over and its audio track the mixer; the old feed is let go
 ├ screen (screen.ts): the feed in front's frames ─► mediabunny VideoSampleSource { codec: "avc", keyFrameInterval: 1, latencyMode: "realtime", sizeChangeBehavior: "contain" } (a keyframe at a switch; a 250 Hz tick re-adds the last picture when a frame's time passes with no new one, so the file stays at the frame rate)
 │   the feeds' audio tracks ─► one AudioContext's MediaStreamAudioDestinationNode ─► its track's chunks ─► AudioSampleSource { codec: "aac", bitrate: 192e3 }
 │       └ Output(Mp4OutputFormat({ fastStart: "fragmented" }), StreamTarget(dataWritable("recordings/<id>/screen.mp4"), { chunked: false }))
 ├ mic: getUserMedia({ audio: { deviceId, echoCancellation: true, noiseSuppression: true, autoGainControl: true } }) ─► "mic.m4a" (AAC 160k) + a 50 Hz RMS log ─► "mic.levels"
 ├ camera: getUserMedia({ video: { width: 1280, height: 720, frameRate: 30 } }) ─► "camera.mp4" (H.264, 3 Mbps)
 ├ events: the feed in front's input.subscribe → batches ─► "events.jsonl" (250 ms batches, t relative to t0); each new feed's subscription opens with its box, nav and load
 ├ holds: runtime.keepAlive("recording"), power.preventSleep() (each feed holds its own tab)
 └ ui.setStatus({ text: "● 0:42", actions: [pause, stop] }) every second; ui.onStatusAction
```

- **The clock.** Every event's `t` is `pistachio.runtime.now()` (epoch ms, sub-ms, main's clock); `t0` is the arrival of the first frame or chunk the screen encoder takes (read through `MediaStreamTrackProcessor`) less one frame, and the sidecar's `t` is `t − t0`. Every frame and chunk of `screen.mp4` is stamped on the same clock by the engine (the writer's media time, pauses taken out; a frame's is its arrival less one frame, the capture's latency), never by the track it came from — which is what lets a switch of tabs be a switch of what is fed and nothing else; the chunks run on the mixer track's own clock from the first's arrival, anchored again after a pause. Zooms ease over ~600 ms, so a frame of skew is invisible.
- **Pause** / **resume**: the screen encoder drops frames and chunks while paused (its stamps leave the span out, the tick starts again at the resume); the mic's and the camera's are mediabunny's `pause()`/`resume()`, which offset their timestamps the same; `{"k":"pause"}`/`{"k":"resume"}` go into the events so the timelines agree.
- **Disk.** Fragmented MP4 everywhere, unchunked (mediabunny writes once a fragment of ≥ 1 s is complete, so a crash loses about a second; a 4 MiB chunk held 10–50 s of screen content in memory — measured); `files.data.freeSpace()` before and every 10 s.
- **The other files' zeros.** The mic and the camera are outputs of their own, each with its own time zero (its first sample); the meta line's `offsets` (ms from `t0`) say where they start, and the editor and the export read source second `s` from their `s − offset / 1000`.
- **Finalize.** `output.finalize()` on each, then a thumbnail (`thumb.jpg`: a frame at 1 s drawn to a 480 px canvas), then `project.json` with the solved defaults (§4), then `ui.openPage("editor", { query: "rec=<id>" })`.
- **The panel** is a page (`panel.html`) that talks to the worker through `runtime.sendMessage` / `runtime.connect("panel")`: it never captures itself.
- **Exports** are the engine's too (`src/engine/exports.ts`, §5): the editor asks, the engine runs them, so an export outlives the editor's window.

**`events.jsonl`** (one object a line; coordinates in the view's CSS px; `t` in ms from `t0`):

```jsonl
{"t":0,"k":"meta","source":{"kind":"tab","tabId":"t_91","title":"Linear","url":"https://linear.app/team"},"capture":{"w":3200,"h":1800,"dpr":2},"view":{"w":1600,"h":900},"fps":60,"startedAt":1761836652000,"offsets":{"mic":41.3},"cursorBaked":true}
{"t":412.6,"k":"move","x":801.5,"y":312.0}
{"t":980.1,"k":"down","button":"left","x":812,"y":318,"target":{"x":760,"y":300,"w":120,"h":36,"role":"button"}}
{"t":1102.0,"k":"cursor","type":"text"}
{"t":1300.2,"k":"focus","rect":{"x":420,"y":180,"w":760,"h":44},"secret":false}
{"t":1320.9,"k":"key","kind":"char"}
{"t":1388.3,"k":"caret","rect":{"x":436,"y":190,"w":2,"h":24}}
{"t":5200.0,"k":"nav","url":"https://linear.app/…","title":"Issue LIN-42"}
{"t":5203.0,"k":"box","view":{"x":312,"y":88,"w":1600,"h":900},"visible":true}
```

Every position is put in `view`'s units as the log is parsed (`inViewUnits`; `projectFor` does the same to the writer's events when the engine solves the first project at the end of a recording): a window resized mid-recording reports a `box` of another size and the input after it in that size's units, while the capture's frames, whatever their size, are drawn stretched into the same frame — a fraction of the view is what lands right. The log itself is read through its streaming address (`files.data.url`), since `files.data.read` answers at most 64 MB and a long recording's log grows past that. The editor scales coordinates by `capture.w / view.w`. `view` is the view as the input subscription reported it (its `box`), and `capture.dpr` what the capture came to over it — not the scale asked: main caps a capture at 3840 on its long side, so a 2560×1440 view at 2× is 3840×2160, 1.5× (`metaFor`). `cursorBaked: true` says the system cursor is in the screen's pixels (R5): the editor offers Smooth and Glide only when it is `false`. Besides the input, the engine writes a `{"t":…,"k":"frame"}` line per captured frame, so the speed plan knows when the page painted.

## 4. The solvers (`src/lib/`, pure, tested)

**`project.ts`** — `project.json`, the only thing the editor writes; raw media is never modified. One dialect, `writeProject` / `readProject`, for the engine and the editor: JSON has no Infinity, so a speed segment's `rate` of Infinity (a cut) is written `"Infinity"` (and `null` or `1e999` read back as Infinity too); `readProject` repairs and clamps what it reads, never throws:

```jsonc
{ "v": 1,
  "cuts": [{ "in": 0, "out": 83.2 }, { "in": 91.0, "out": 140.5 }],                    // source seconds kept
  "zooms": [{ "id": "z1", "start": 3.1, "end": 7.9, "level": 2.0, "center": [0.42, 0.31], "auto": true, "ease": "spring", "follow": true }],
  "speed": [{ "start": 10.2, "end": 14.8, "rate": 4, "auto": "idle" }, { "start": 20.0, "end": 26.5, "rate": 2, "auto": "typing" }],
  "look": { "background": { "type": "wallpaper", "id": "dawn" }, "padding": 0.08, "radius": 14, "shadow": 0.6, "frame": "browser", "aspect": "16:9" },
  "cursor": { "mode": "natural", "size": 1.6, "smoothing": 0.6, "hideIdle": true, "click": "ripple" },
  "camera": { "shape": "circle", "size": 0.18, "corner": "br", "shrinkOnZoom": true },
  "audio": { "mic": 1.0, "page": 0.6, "muteSpedUp": true },
  "export": { "format": "mp4-h264", "height": 1080, "fps": 60, "quality": "high" } }
```

**`zoom.ts`** — events → zoom segments. Interests: a left `down` (its `target` rect when under 40% of the view, else a box around the point at the default level), a `focus` rect (weight 0.8), a typing burst (char keys closer than 450 ms: the union of the caret rects, else the field, else around the pointer). Merge an interest into the open segment when it starts within 1.0 s of the segment's end, no breaker lies between (a `nav`, a scroll run over 0.6 s, a `box` change, a pause) and the union still fits at ≥ 1.25×; the segment keeps the interests' centres as pan anchors. Then: `start = t0 − 0.35`, `end = max(t1 + 1.4, start + 1.4)`, `level = clamp(fitZoom(rect padded 18%), 1.25, 2.5)` (a target under 2% of the view caps at 2.0; the cap is `min(2.5, dpr × 1.25)` so content never goes soft), cut at the next breaker; overlaps at similar levels (within e^0.3) merge into a pan, else the earlier ends.

**`camera.ts`** — the path. A critically damped spring per axis, exact integration, ω = 7 (Mellow; Quick 10, Slow 5), zoom in log space, four substeps a frame; inside a segment the target pans between anchors and, with `follow`, keeps the cursor (looked up 150 ms ahead) inside the middle 60% of the viewport; the viewport is clamped inside the frame. A jump farther than a zoomed viewport uses van Wijk–Nuij's out-across-in path (ρ ≈ 1.4, 0.8–1.0 s). Edited segments replace auto ones in the same lane; `ease` is `spring` | `smooth` (cubic, fixed duration) | `cut`.

**`cursor.ts`** — the path: resample moves to 120 Hz; `natural` returns it; `smooth` runs the same spring (ω from 40 tight to 12 floaty by the slider); `glide` simplifies (Douglas–Peucker, 6 px) and interpolates (centripetal Catmull–Rom); every click blends back to the raw position over −120/+80 ms. Idle: fade out after 2 s still, back in on a 3 px move. Click: the sprite scales to 0.85 for 90 ms; a ring 0 → 28 px × size over 400 ms, ease-out, alpha 0.45 → 0. A vector cursor set keyed by `cursor` shape: arrow, pointer, text, grab, grabbing, the resize shapes, not-allowed, wait.

**`speed.ts`** — idle (no input within ±0.3 s, no pointer move over 3 px, and no captured frame — tab capture sends frames only when the page paints) longer than 1.5 s: keep 0.4 s of head and 0.3 s of tail, then a rate of `clamp(len / 0.6, 2, 8)`, or a cut with a 120 ms crossfade past 6 s; typing bursts of ≥ 10 keys over ≥ 2 s at 2× (3× past 6 s); loads over 1 s at 4×; never while the mic hears speech (`mic.levels` over −40 dBFS for 300 ms, 200 ms hangover — the levels run on the mic file's clock and are read from where it starts on the source's, its `offset`) and never within 0.5 s of a click; segments under 0.5 s dropped; rates eased over 250 ms. **`timemap.ts`**: `tOut(tSrc) = ∫ 1/rate` over the kept cuts, inverted into a table at the output fps.

**`render.ts`** — `render(ctx, tOut, project, sources)` per R3; the background blur cached while static; the shadow a pre-rendered 9-slice; the window chrome as vectors (the browser frame's address from `nav` events); `drawImage(VideoFrame)` zero-copy; the camera bubble masked to a circle, shrinking past 1.4× when asked; keystroke chips from `chord` events only.

## 5. The editor and the export

The editor page loads `project.json` and the media by `files.data.url(...)` (served with Range support, so `<video>` seeks); playback is two `<video>`s (screen, camera) and an audio element (mic) driven by `requestVideoFrameCallback`, `playbackRate` per speed segment (≤ 16×, `preservesPitch`), cuts as seeks (the 1 s GOP makes them cheap); the preview renders at the panel's pixel size. Frame-exact stepping and scrubbing read samples through mediabunny's `Input` + `VideoSampleSink`. The solvers re-run on edits that change their inputs; `project.json` is written debounced (500 ms) through `files.data.write`.

**Who runs it.** The engine, in the extension's worker, which outlives the editor (`src/engine/exports.ts`). The editor's sheet is a client: Export sends `runtime.sendMessage({ type: "exportStart", recordingId, urls, project, meta, name, destination, title })` — the project as `project.json`'s text, since a cut's rate is Infinity — and the engine checks it, opens `exports/<name>`, holds the worker up (`runtime.keepAlive("export")`), spawns the export Worker from the extension's root (`new Worker(new URL("/src/export/export.worker.js", location.href), { type: "module" })`: the worker's page is `/__pistachio__/worker.html`, the build puts the Worker at `src/export/export.worker.js`) and answers; a second start while one runs is answered with an error. The engine pushes `progress` (with an ETA), `done` (the finished export), `error` and `cancelled` on every editor's `runtime.connect("export")` port; an editor that opens asks `{ type: "exportState" }` and shows a running export of its recording, or its finished card (the card's media is `files.data.url(dataPath)`, which a page reads). *Cancel export* is `exportCancel`; the card's ✕ is `exportDismiss`. On `done` the engine does what the sheet did until 2026-11-02: `files.save(…, { folder: "screenshots" })`, then the destination — `files.reveal`, `clipboard.write({ filePath })`, or `notes.create` — then the *Exported* notice, whose *Show in Finder* comes back to the worker (`ui.onToastAction`: a notice's button is always heard in the worker). Every one of those runs from the worker (`main/extensions/methods.ts` limits none of them to a page or a gesture); only the card's drag (`files.startDrag`, the dragging view's own) and its buttons stay in the page. The `?fake=1` dev kit runs the same job keeper in the page, over its shim and its stand-in Worker (`localExports`).

Export runs in a module Worker (`src/export/export.worker.ts`, messages in `src/export/protocol.ts`): `Input` over mediabunny's `UrlSource` on the recording's `files.data.url`s (same origin; it reads with `Range: bytes=<from>-` and the 206 answers), a forward `VideoSampleSink.samples(start)` per kept range of the frame schedule (a cut seeks, a sped-up stretch decodes through and holds the last frame), `OffscreenCanvas` + `render` with the state from `renderStateFor` (`src/lib/render.ts`; the editor's preview builds the same one, so both draw the same frame) at the lib's `outputSize` (the preview's shape too), `CanvasSource({ codec, keyFrameInterval: 2, hardwareAcceleration })`, audio decoded with `AudioSampleSink` and remapped through the time map (both the mic and the page's sound cut where the map cuts, and both following *Mute while sped up* as the preview does: *dropped* inside sped-up stretches when `muteSpedUp`, else sped up in step, naively resampled; every silence and cut faded over 30 ms; `soundPlan` in `src/export/audio.ts`), mixed at 48 kHz stereo into `AudioSampleSource` (AAC 192 kbps in MP4, Opus 160 kbps in WebM). The bytes go to the engine as numbered chunks of ≤ 4 MiB, four unanswered at most, which it appends through `files.data.open("exports/<name>")` (append-only), then `files.save({ dataPath }, { suggestedName, folder: "screenshots" })`, then the destination. A muxer that seeks back is staged in a temporary OPFS file (a dedicated Worker's sync access handle) and sent once finished: MP4 `fastStart: "reserve"` (moov up front), WebM with cues and duration; where OPFS is missing or its quota would not hold 1.5× the target size, the muxer only appends instead: a fragmented MP4 (2 s fragments; QuickTime/AVFoundation read it, measured) or an append-only WebM (no duration). Ladder by `isConfigSupported`: HEVC hardware → H.264 hardware → H.264 software; H.264 hardware → software; VP9 → VP8; else the error "No encoder here can make …". Size: the export height is the short side (9:16 at 1080p is 1080×1920), both sides even. Bitrate: 0.07 / 0.12 / 0.2 bits per pixel per frame at 30 fps for Standard / High / Studio, × (fps/30)^0.75, × 0.6 for HEVC, × 0.65 for VP9 (High: 7.5 Mbps at 1080p30, 12.6 at 1080p60, 50 at 4K60), VBR. GIF: gifenc 1.0.3, 960 px on the long side, 15 fps, ≤ 20 s (longer is refused), one palette from twelve frames across the clip, no dither, delays alternating so the clip keeps its length. Progress every 30 frames with an ETA; cancel aborts the output and the engine removes the partial file (an error too, with a notice: the editor may be closed).

## 6. Files and gates

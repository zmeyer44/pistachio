# Patches

pnpm applies these at install (`pnpm.patchedDependencies` in the root `package.json`). Each dependency is pinned to the exact version its patch was written against; an upgrade re-applies every hunk below by hand, checks each one still says what it says here, and re-runs the probes named under each library.

To change a patch: `pnpm patch <name>@<version> --edit-dir <dir>` (the folder comes with the current patch applied), edit, `pnpm patch-commit <dir>`. Every hunk in the code carries a `// pistachio:` comment with its reason.

## playwright-core@1.62.1

`lib/coreBundle.js` ≈ 34796: a CDP command response that arrives after a target crash already rejected its callback is dropped instead of tripping an assertion that kills the Node process.

Probed on Electron 43.4.1 (2026-10-30): a web page's `crx-msg` naming an installed extension is refused; an extension page's naming another is refused, its own works; `crx-msg-remote` has no handler; `crx-add-listener` from a page leaves no listener; an extension without `cookies` gets nothing, one with `cookies` and `http://127.0.0.1/*` reads and hears only 127.0.0.1's; `tabs.query`/`onUpdated` hide a tab outside the host grant; `tabs.update` to `pistachio:`/`file:` is refused and to `https:` reaches `navigateTab`; `insertCSS` without a host grant is refused; worker messages (context menus, badges) pass.

**Not patched, stated:**

- The frame preload is registered for every frame of the session and returns at once off `chrome-extension:`; the service-worker preload runs in **every** service worker of the session, a website's included, and exposes a `chrome` stub and an `electron` bridge there — fingerprintable; every call it makes is refused by hunk 16.
- `tabs.executeScript`, `tabs.removeCSS`, `tabs.sendMessage` and `chrome.scripting` are Electron's own (not overridden by the library) and use Electron's permission checks.
- Host checks read the manifest only: origins granted later through `permissions.request` (recorded in the library's `permissionMap`) don't count — refused rather than widened. `compat.ts` lets `permissions.request` ask only for origins the manifest declared.
- `matchesPattern`'s loose regex still serves `contextMenus`' `documentUrlPatterns`/`targetUrlPatterns` and `tabs.query`'s URL filter (the latter only over tabs the extension may see).
- `contextMenus.onClicked`'s `pageUrl`/`linkUrl`/`srcUrl` are sent with a scrubbed tab: the person chose the extension's own item, as Chrome's `activeTab` grant does.
- Native messaging: Chrome's host directories and `userData/NativeMessagingHosts` are searched, the framing is wrong for non-ASCII, and a split stdout chunk throws in main. Password managers stay ◐.
- `windows.remove` of Pistachio's window: the library drops the window from its set before asking the app; `compat.ts` closes nothing and puts it back.
- `commands.onCommand` never fires (no shortcuts); `runtime.onInstalled` never fires on load (Electron, measured).
- No per-extension redaction inside `browserAction.getState` (titles, badges): main is its only caller now.
- `PopupView` sizes and shows itself on `preferred-size-changed`, which Electron 43 never emits for it (measured 2026-10-30: 25×25, hidden). `compat.ts` `fitPopup` measures the popup page instead and calls PopupView's own `setSize`/`updatePosition`/`show`; it is not a patch.
- `handleCRXProtocol` registers `crx` when it is called, and a page keeps the handlers it committed with, so the shell would never see it. main registers `crx` on the default session at launch and forwards to `compat.ts` `crxResponse`, which is the static handler's body.
